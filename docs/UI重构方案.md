# UI 与交互反馈重构方案（v1 · 审计 + 风格候选）

> 状态：**正式站已落地第一版：全站京华老宋体、22px 字号基准、五套配色（青瓷/朱墨/松烟/藕荷/海派）与 motion.css 交互层；待审稿**。本文做审计与方案；可点击样张在 `proto-ui/`（A/E 两套、四画面、并排对比），主题板在 `proto-ui/theme.html`（五套主题、明暗切换、色板/字体/组件/材质；组件配方取自 StyleKit Editorial / Ink Wash / Wabi-Sabi / Japanese Fresh，标题 Noto Serif SC、正文寒蝉锦书宋 Text、楷体 LXGW WenKai、元信息 Noto Sans SC / IBM Plex Sans / Fraunces），宋体对比在 `proto-ui/font-test.html`，真实作品页在 `proto-ui/work-v4.html`；均不参与正式构建。
> 范围：全站视觉系统、页面布局、交互反馈、动效与可访问性；不改 Eleventy 架构、不改作品 URL、不动内容数据。
> 依据：`src/static/site.css`（670 行）、`site.js`、`auth.js`、`zhuzhu.js`、各 `.njk` 模板与 `npm test` 基线。

## 0. 一句话结论

> **2026-11-01 修订**：A/E 全站样张经对比被认为不如原站；方向改为**保留原站骨架，只做主题层**。主题板 v1 见 `proto-ui/theme.html`：青瓷·雨过（主）/ 朱墨·双色（期页）/ 松烟·夜读（深色）/ 藕荷·词笺（春季）/ 海派·墨金（特刊）。本文 §1 审计与 §4 P0 仍有效；§2 的 A/E 只作历史参考。

现在的站已经有很好的“纸、墨、宋体、朱砂、直角、留白”底子，**不要推倒重来**；应该做的是：

1. **先修交互反馈的硬伤**（重复提交、弹窗、加载态、焦点、空状态）；
2. **把零散样式收成一套 token 与反馈语法**；
3. **保留原站骨架，只换主题层**：纸色微调 + 一个副色 + 材质/字重，不重排 logo、导航、hero、社训与各页结构。

推荐的组合不是“选一套皮”，而是“**固定骨架 + 可换主题层**”，这样既有新意，又不会把长文阅读和手机端拖垮。

### 1.2 现有视觉基因（应该保留的）

- **纸色**：`--paper-lt:#eef0e6`、`--paper-deep:#e4e7d9`；深色为 `#171512`。
- **墨色**：`--ink:#26221a`、`--ink-soft:#544e42`、`--dim:#6e6a5e`，不用纯黑。
- **朱砂**：`--seal:#9c3f30`，只做强调，不铺大面积。
- **字体**：标题 `Noto Serif SC`；正文 `寒蝉锦书宋 Text Regular`（OFL 1.1，横画更实，Windows 屏幕更稳）；楷体用于题记、自注、序跋。
- **版式**：最大宽度 `1120px`；直角、细线、无阴影；大量留白。
- **已有的好动效**：深浅色“滴墨晕开”（`site.js` 的 `bloom()` + `.ink-veil`）非常契合气质，应该保留并作为全站动效语言的基准。
- CSS 头部已注明 `taste-skill` 的三个旋钮：`VARIANCE 6 / MOTION 3 / DENSITY 3`。这次重构可以理解为**把旋钮从“靠手写”变成“有 token、有规则”**。

### 1.3 现有交互反馈审计

| 场景 | 现在怎么做 | 问题 | 目标 |
|---|---|---|---|
| 页面进入 | `.rv` 滚动显现，0.8s | 所有元素同一节奏；动态插入的行刻意不带 `.rv`，所以筛选后没有过渡 | 统一时长/错峰；筛选结果用轻量过渡 |
| 导航 hover | 只变朱砂色 | 颜色是唯一信号；没有下划线/位移；`aria-current` 缺失 | 颜色 + 细下划线滑入；补 `aria-current` |
| 按钮 | `.btn` hover 变深、active 下压、focus-visible 描边 | 基本可用；次按钮/文字按钮状态不统一 | 统一三态 + 禁用态 + loading |
| 深浅色 | 三滴墨晕开，约 0.94s | 很好，保留；`prefers-reduced-motion` 已处理 | 作为“纸/墨”反馈语言的标准 |
| 作品库筛选 | 立即 `display:none`，计数更新，写 URL | 结果瞬间消失/出现，没有过渡；无骨架屏 | 计数 + 行淡出/重排 160–220ms；首屏骨架 |
| 关联“换一批” | `innerHTML` 直接换 | 没有过渡，像闪一下 | 淡出/淡入或轻微错位 |
| 标签投票 | fetch 成功后重新加载整块 | 没有 pending/禁用；连点可能重复；成功只靠一行字 | 乐观变红 + 计数；失败回滚；按钮短暂禁用 |
| 评论/回帖 | fetch 后 `loadAll()` | 没有 disabled/loading；连点会重复提交；成功后新楼没有高亮 | 提交按钮 loading；成功后新楼闪光；失败保留草稿 |
| 同感 | 立即改按钮和计数 | 没有 pending；失败后可能显示错 | 乐观更新 + 失败回滚 |
| 登录/注册弹窗 | 自绘 `.zz-authbox`，`role="dialog"` | 没有 Escape 关闭、没有点背景关闭、没有 focus trap、没有 `aria-modal`；登录按钮可连点；恢复码用 `window.alert` | 完整弹窗规范；恢复码改为可复制的面板 |
| 投稿 | 左写右预览，提交有 disabled/loading/错误 | 体验已不错；成功后的下一步（PR 链接/复制）可以更清楚 | 成功面板 + 复制链接 + 继续投稿 |
| 入社 | 内联脚本 fetch `/api/join` | **`site.js` 里还保留了一套旧的 Netlify 提交逻辑，同一个表单会触发两次请求**（详见 §1.4） | 只保留一个提交源；字段级错误 |
| 空状态 | 作品库一行“没有符合条件的作品。” | 太干；没有下一步动作 | 一句古意文案 + “清除筛选”按钮 |
| 加载态 | 投稿预览有“正在排版…”；其余几乎没有 | 评论/标签/关联加载时是空白或旧内容 | 骨架屏/局部 loading，不用全屏转圈 |
| 错误态 | 内联 `.form-msg` / `zz-msgline` | 样式与文案不统一；网络错误和技术错误混在一起 | 统一“人话错误 + 重试” |
| 焦点 | 部分 `:focus-visible` 有描边；输入框 focus 只变边框色 | 键盘用户看得不够清楚；弹窗打开后焦点不锁定 | 全站 2px 墨色 focus ring；弹窗 focus trap |
| 触屏 | 标签释义长按 500ms 显示 | 好；但很多信息仍只靠 hover `title` | 触屏可点的说明入口 |
| 动效 | 0.2s 颜色过渡 + 0.8s 入场 + 0.94s 滴墨 | 没有统一的时长/缓动 token | 120/200/320/600ms 四档 |

### 1.4 审计中发现的真实 bug / 风险

1. **入社表单重复提交（P0）**
   - `src/index.njk` 的内联脚本把表单 POST 到 `/api/join`；
   - `src/static/site.js` 里还保留着旧的 Netlify Forms 逻辑，把同一个表单 POST 到 `/`；
   - 两个 `submit` 监听器都会执行：一个成功、一个失败，后到的错误提示可能覆盖成功提示，线上还会产生一次无效请求。
   - 处理：删除 `site.js` 的旧表单块，只保留一个提交源；或把内联逻辑迁进 `site.js`，二选一。

2. **登录弹窗可访问性不足（P0）**
   - 无 Escape 关闭、无背景点击关闭、无 focus trap、无 `aria-modal="true"`；
   - “注册成功”用 `window.alert` 展示恢复码，不可复制、打断流程；
   - 登录按钮没有 loading/disabled，连续点击可能发多次请求。

3. **众注提交没有 pending（P0）**
   - `postComment()` 与 `like()` 都是“发请求 → 重新加载”，按钮不置灰；网络慢时用户会重复点；
   - 标签投票失败只显示一行字，已变红的 UI 可能和服务端不一致。

4. **筛选结果无过渡（P1）**
   - `library.njk` 直接改 `display`，列表高度突变；手机端尤其明显。

5. **颜色硬编码（P1）**
   - 大量 `rgba(156,63,48,…)`、`rgba(38,34,26,…)` 直接写在组件里，没有走 token；深色模式需要逐条覆盖。

6. **字体外链（P1）**
   - `head.njk` 仍从 Google Fonts 加载 Noto Serif SC，大陆偶发不稳定；重构时应决定“自托管子集 / 系统字体栈 / 保留外链”。

7. **标题与数字提示只靠 `title`（P2）**
   - 统计口径、标签释义等放在 `title` 里，触屏和键盘用户不容易看到；可加可聚焦的“说明”按钮。

### A. 现代社刊 · 编辑设计（主推）

- **关键词**：大标题、细线、目录、页码、留白、宋体正文 + 无衬线小字。
- **参考**：StyleKit 的 Editorial / Magazine Grid、Newsprint 家族；《巴黎评论》《Granta》一类文学刊物的版式逻辑；不要照搬欧美杂志的彩色大图，保留纸墨色。
- **视觉规则**：
  - 12 栏网格，桌面 `1120–1200px`，正文行宽 `32–38em`；
  - 标题用大字号宋体，元信息用系统无衬线小字（作者、体裁、时间、页码）；
  - 只用细线分隔，不用卡片阴影；重要数字（期号、年份）可放大作版面锚点；
  - 保留朱砂作“印”，不大面积铺色。
- **交互语言**：翻页/淡入、目录行下划线滑入、筛选结果重排；动效克制。
- **适用页面**：首页、作品库、作品页、社员、期页、概念页——**全站骨架**。
- **风险**：做不好会像“普通杂志模板”；需要靠字体、留白、目录细节和中文标点建立辨识度。
- **成本**：中。

### B. 文人信笺 · 手札（主推为“反馈语气”）

- **关键词**：笺纸、朱丝栏、行距、批注、印章、手写感。
- **参考**：十竹斋笺谱、周作人/鲁迅书札、StyleKit 的 Artistic / Watercolor、Cultural / Regional；只取“信笺”的秩序，不取满屏花纹。
- **视觉规则**：
  - 暖纸色、细横线/竖线、窄行宽、页边批注位；
  - 楷体只用于题记、自注、序跋、少量提示，不用于正文长读；
  - 印章作为“确认/落款”，不做满屏装饰；
  - 可加非常轻的纸张纹理（CSS 渐变或低透明度噪点），不要贴图。
- **交互语言**：提交成功“落印”、标签投票“点朱”、弹窗像“展开信笺”、Toast 像“批注条”。
- **适用页面**：作品页题记/自注、投稿成功、登录/注册、众注区、页脚落款。
- **风险**：容易变成“古风模板”；手写字体和纹理过多会降低可读性；移动端行宽难控。
- **成本**：中高（需要自定义纹理、印章、细节）。

### C. 宋版刊刻 · 古籍版式

- **关键词**：版框、界行、鱼尾、牌记、藏书印、竖排标题。
- **参考**：宋刻本影印、书格（shuge.org）等古籍扫描；StyleKit 的 Cultural / Regional。
- **视觉规则**：
  - 外框 + 细界行；标题可局部竖排（只做标题，不做正文）；
  - 米黄纸、墨色、朱印；重要页面加“牌记”式信息块；
  - 目录用“卷/期/篇”的层级。
- **交互语言**：翻页、木刻显现、印章落下。
- **适用页面**：期页封面、概念页、专题页、首页“刊期档案”区。
- **风险**：整站使用会显得沉重、移动端难排；竖排正文不可取。
- **成本**：高。

### D. 民国书刊 · 双色印刷

- **关键词**：双色印刷、老宋体、几何分割、封面大字、错位套色。
- **参考**：民国杂志封面、《良友》画报、鲁迅设计的书封；StyleKit 的 Retro/Vintage + Art Deco。
- **视觉规则**：
  - 墨黑 + 朱红/靛蓝双色；大面积留白与粗线分割；
  - 封面/期页可用竖排大字、几何色块；
  - 正文仍保持现代横排，避免阅读负担。
- **交互语言**：套色错位 hover、印章、幕布式切换。
- **适用页面**：期页、概念页、专题封面、首页“雅集”区。
- **风险**：历史联想较强，需避免宣传画式的符号；双色对比要过可读性。
- **成本**：中。

### E. 水墨留白 · 东方极简

- **关键词**：留白、淡墨、渐变、呼吸、单焦点。
- **参考**：水墨画、原研哉式留白、StyleKit 的 Nature / Cozy、Japanese minimal。
- **视觉规则**：
  - 每屏一个焦点；大量空白；淡墨渐变；极少线条；
  - 正文宋体、行高偏大；按钮退到“文字 + 细线”。
- **交互语言**：墨迹扩散、淡入淡出、慢节奏。
- **适用页面**：首页 Hero、概念页、404、过渡页。
- **风险**：容易“空得像没设计”；信息密度低，作品库/筛选不适合。
- **成本**：低–中。

### F. 孔版 Zine · 独立刊物

- **关键词**：双色/三色、网点、错版、粗体、贴纸、年轻。
- **参考**：Risograph zine、独立文学刊物；StyleKit 的 Artistic / Print、Brutalist-lite。
- **视觉规则**：
  - 朱砂 + 靛蓝 + 米色，不用荧光色；
  - 大字号标题、错位色块、网点纹理；
  - 只用于“投稿/社区/活动”区域，不用于正文长读。
- **交互语言**：印章、套色偏移、快速 120ms 反馈。
- **适用页面**：投稿页、众注区、活动/征稿、期页副刊。
- **风险**：太潮，容易过时；整站使用会削弱“文学社”的沉静感。
- **成本**：中。

### G. 海派 Art Deco · 摩登几何

- **关键词**：几何边框、放射线、对称、细双线、旧金。
- **参考**：1930 年代上海月份牌/建筑装饰；StyleKit 的 Art Deco。
- **视觉规则**：
  - 对称框、扇形/放射线、细双线；墨 + 米 + 朱 + 少量哑金；
  - 只做封面/分隔/页脚，不做正文容器。
- **交互语言**：金线绘制、幕布拉开、印章。
- **适用页面**：期页封面、周年/专题、页脚。
- **风险**：装饰性强，容易像婚礼/餐厅请柬；金色在深色模式难控。
- **成本**：中高。

### H. 博物图鉴 · 档案标本

- **关键词**：标本标签、编号、细线表格、档案袋、小字注释。
- **参考**：植物图鉴、博物馆藏品目录；StyleKit 的 Nature / Cozy + Editorial。
- **视觉规则**：
  - 作品 = 标本卡：编号、题名、作者、体裁、创作时间、标签；
  - 元信息用等宽/小号字；细线表格；少量印章；
  - 适合“作品库/全文库/期册”这种检索型页面。
- **交互语言**：标签滑入、卡片翻面、盖章。
- **适用页面**：作品库、全文库、期页目录、社员档案。
- **风险**：偏冷、偏科学；需要靠纸色和中文排版把它拉回文学气质。
- **成本**：中。

### I. 碑帖金石 · 拓片

- **关键词**：拓片、斑驳、黑白、厚重、金石。
- **参考**：碑帖拓片、金石学；StyleKit 的 Brutalist / Cultural。
- **视觉规则**：
  - 深炭底、石纹、放大字；朱印点缀；
  - 只适合标题/封面/分隔，不适合正文。
- **交互语言**：凿刻、落尘、重压。
- **适用页面**：404、专题封面、页脚印章。
- **风险**：太暗、太沉重；长文阅读不友好；素材成本高。
- **成本**：高。

### J. 素笺无印 · 安静极简（备选）

- **关键词**：无装饰、细线、均匀、克制。
- **参考**：MUJI、日式编辑设计；StyleKit 的 Minimal。
- **视觉规则**：单栏、宽边距、系统字体、一个强调色；几乎无动效。
- **交互语言**：120ms 透明度/位移；不打扰。
- **适用页面**：全站可做，但会失去现在的“社刊”辨识度。
- **风险**：容易像文档站；需要靠内容与排版撑住。
- **成本**：低。

### 推荐组合

**主推：A + B + D/H 局部**

- **A 现代社刊**：全站骨架（首页、作品库、作品页、社员、期页）。
- **B 文人信笺**：反馈语气（题记/自注、登录弹窗、投稿成功、众注、页脚落款）。
- **D 民国书刊**：期页/专题封面（每期一个“封面版式”）。
- **H 博物图鉴**：作品库/全文库的“档案卡/索引”细节。
- **E 水墨留白**：如果你们更想要安静，可把 A 换成 E，但仍建议保留 B 的反馈细节。

**不建议整站使用**：C 宋版、F Zine、G Art Deco、I 碑帖——它们适合局部，不适合长文阅读与移动端。

## 3. 交互反馈系统（重构时按这套做）

### 3.1 四种反馈语言

| 语言 | 用途 | 表现 |
|---|---|---|
| **纸** | 容器、卡片、面板 | 纸色、细线、直角；不用阴影，用边线与留白分层 |
| **墨** | 内容出现/切换/筛选 | 淡入、晕开、重排；参考现有滴墨换色 |
| **印** | 确认、投票、提交成功 | 朱砂点/印章落下；短促、明确 |
| **笺** | 提示、校验、批注 | 小字、楷体、边注；不抢主内容 |

### 3.2 动效四档

```css
--dur-1: 120ms;   /* hover / 点按 / 颜色 */
--dur-2: 200ms;   /* 行出现、筛选重排、Toast */
--dur-3: 320ms;   /* 面板、弹窗、抽屉 */
--dur-4: 600ms;   /* 页面/视图切换、滴墨 */
--ease-out: cubic-bezier(.2,.8,.2,1);
--ease-in-out: cubic-bezier(.4,0,.2,1);
```

- 微交互不超过 180ms；
- 弹窗/面板不超过 320ms；
- 页面切换 400–600ms；
- 一律尊重 `prefers-reduced-motion`（现在已有全局关闭，继续保留）。

### 3.3 反馈清单（重构目标）

| 场景 | 目标反馈 | 组件 | 时长 |
|---|---|---|---|
| 导航 hover | 颜色 + 细下划线滑入 | link | 120ms |
| 按钮 hover/active | 朱砂加深 + 1px 下压 | `.btn` | 120ms |
| 按钮 loading | 文案变“正在…” + 禁用 + 细线转圈/墨点 | `.btn[data-loading]` | 持续 |
| 深浅色 | 保留滴墨晕开 | `.ink-veil` | 940ms |
| 作品库筛选 | 计数更新 + 行淡出/重排 | `.idx-row` | 180–220ms |
| 换一批 | 旧批淡出、新批淡入 | `.rel-ul` | 180ms |
| 标签投票 | 立即变红/计数 + 小印章；失败回滚 | `.tag` | 120ms |
| 评论提交 | 按钮 loading；成功后新楼高亮 | `.z-item` | 200ms |
| 同感 | 数字跳动 + 朱砂；失败回滚 | `.z-like` | 120ms |
| 登录弹窗 | 信笺展开；Escape/背景关闭；focus trap | `.zz-authbox` | 220ms |
| 注册恢复码 | 面板内可复制，不用 `alert` | `.recover` | — |
| 投稿成功 | 成功面板 + PR 链接 + 复制 | `.sub-msg` | 200ms |
| 入社成功 | 落印 + 一句人话 | `.form-msg` | 200ms |
| 空状态 | 一句古意文案 + 下一步按钮 | `.empty` | — |
| 加载 | 列表骨架；不用全屏 spinner | `.skeleton` | — |
| 错误 | 字段级内联；全局 Toast/状态条 | `.form-msg` / `.toast` | 200ms |
| 复制链接 | Toast“已复制” | `.toast` | 1600ms |
| 页面切换 | View Transitions（渐进增强） | `document.startViewTransition` | 400ms |

### 3.4 可访问性底线

- 所有交互元素有 `:focus-visible`，用 2px 墨色 ring + 3px offset；不要只靠颜色；
- 弹窗：`role="dialog"`、`aria-modal="true"`、打开时聚焦第一个字段、Tab 循环、Escape 关闭、关闭后焦点回到触发按钮；
- 异步消息用 `aria-live="polite"`（现有 `.form-msg` 已有）；
- 导航当前页加 `aria-current="page"`；
- 触屏不依赖 hover；标签释义保留长按，同时提供可点“?”；
- 色彩对比：`--dim` 在纸色上要过 4.5:1；朱砂小字需检查；
- 动效可关闭；不使用自动播放声音。
