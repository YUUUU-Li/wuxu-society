## P0 · 体验修复（改动小，先做）

### ① 关联作品"每次都那几首"→ 轮换 + 放开

**根因**（已查代码确认）：关联区三条规则各有**数量上限**——同作者 ≤4、同意象 ≤2、同时同源 ≤3，且按固定收录顺序取前几名。所以高产作者（如 zk 有 13 首）永远只显示最早的 4 首，其余作品没有入口。

**方案**：
| 区块 | 现在 | 改为 |
|---|---|---|
| 同作者 | 最多 4 首，固定 | **全部列出**（一行一首，紧凑样式；member 档案页也本来就有该作者全部作品） |
| 同意象 | 最多 2 首，固定 | 4 首，**每周轮换**（用"作品名+周号"做确定性随机，同一周内稳定、每周换一批） |
| 同时同源 | 最多 3 首，固定 | **全部列出**（同源人数有限，全列不臃肿） |

每区标题加计数（如"同作者 · 共 12 篇"）。**验证**：连续两周/多篇作品抽查，确认不同篇目轮流出现、无死链。

### ② 作品库筛选重做

现状：作品库按三个分组平铺长列表，无任何筛选。

**方案**：顶部加一排筛选（纯前端 JS，无后端）：
- **按作者**（下拉/标签，含笔名）
- **按体裁**（五绝/七绝/五律/七律/词/古风/联句/现代诗/散文…）
- **按意象标签**（从 43+ 篇的 imageries 汇总去重）
- **按雅集/出处**（清明首聚、回忆文会、社课…）

列表行渲染时带 `data-author/genre/imageries/source` 属性，JS 过滤 + 实时计数 + "清除筛选"。移动端可用（筛选条可横向滑动）。筛选也能侧面解决"找不到某作者其他作品"的问题。

### ③ 移动端走查

朋友已重构过手机版。做法：**列一份走查清单**，真机/手机模拟器逐项核对（首页 hero、作品卡片、作品页正文行距、关联区、投稿表单、导航折叠）。**需要你提供"哪几个东西显示不对"的具体截图或描述**，逐条修。修的时候注意：CSS 现在全站单一文件（`src/static/site.css`），朋友如也在改，最好**合并成一次提交**避免两人互相覆盖。

### ④ 首页改版

现状问题（待你补充具体观感）：hero 还是外网占位图（picsum）、信息层级偏平。

**方向**（P0 先小改，P2 再大改）：
- 换掉外网占位图 → 纯色/渐变/社内书法或画作（避免图片源失效 + 更贴社风）；
- 首屏加**最新一期/最新收录**入口；
- 作品精选卡片**每周轮换**（同 ① 的确定性随机），首页不再永远同一批。

## P1 · 评论系统 + 表情 + 众注意象（核心新功能）

### 你的原始诉求拆成三层

1. **即时反应**：每篇作品旁一排"表情/颜文字"，一点即达（水源味）；
2. **短评/感受**：读者写一两句自己的感受、情绪、读到的东西；
3. **意象众注**：你觉得 AI 总结意象不行 → 让"人"来注：每篇作品可增补"意象注解"（谁、注了哪个意象、一句阐释），这些注释**可选精选**后进入作品页的意象展示，甚至影响自动关联。

### 技术选型（静态站没有后端，必须选一个"评论托管"）

| | **Waline（推荐尝试）** | **Giscus** | **Twikoo** |
|---|---|---|---|
| 评论形态 | 游客可匿名评（昵称+邮箱可不填），有表情选择器(OwO，可自定义颜文字/表情包图) | GitHub Discussion 评论区 | 同 Waline 类 |
| 登录门槛 | **无需任何账号** ✅ | 必须有 GitHub 账号 | 无 |
| 表情/反应 | 评论内表情 + 可加"喜欢"反应 | 有 reactions（同样要登录） | 评论内表情 |
| 部署 | 后端可放 **Netlify Functions（与站点同域）**，前端一行 JS | 只需开 GitHub Discussions + 授权 app | 后端一般放 Vercel/腾讯云，大陆访问可选性多 |
| 数据存哪 | 需另选一个免费数据库（LeanCloud 国际版 / Upstash 等），**大陆访问稳定性要实测** | GitHub（零额外服务） | 腾讯云/其他 |
| 风格定制 | CSS 可深度改造成纸面古风 | 官方主题 + CSS 变量，改造余地小些 | CSS 可改 |
| 工作量 | 中（前后端 + 数据服务注册） | 小 | 中 |

**建议**：文学社读者大多没有 GitHub 账号，**Waline 最接近"水源社区"的体验**（游客直接评 + 表情）。风险点是免费数据库在大陆的稳定性——上线前用真机测一周。若想零运维，Giscus 是退路。

### 评注风格（朋友提的"风格要调"）

不做通用论坛样式。**统一为"笺注"风**：评论区标题用"众人笺"之类；头像弱化、昵称用短款；表情包只收"社风"颜文字/emoji 集（如 👏🌙🍵✒️😢🤍），不接入通用大表情库；评论卡片用现有纸面边框体系。

### 意象众注（v2 再上，机制现成）

意象注解本身就是"内容投稿"→ **复用投稿 PR 机制**：投稿类型扩展为"作品投稿 / 意象注解"，注解经编委合并后变成作品页的"集注"区块。这样注解有审核、有署名、可溯源，也不会被垃圾淹没。

## P2 · 刊期机制 + 概念化（大改，先定模型）

### ⑤ 投稿"集中成一期"

诉求：投稿零散进来，想**攒一段时间整理成一期**，方便归档阅读。

**数据模型草案**：新增 `src/_data/issues.json`：
```json
[
  { "no": 1, "name": "第一卷 · 癸卯秋社", "period": "2026-09 ~ 2026-10",
    "lead": "本期辑语……", "slugs": ["w-feng", "w-zhuyingtai", "..."] }
]
```
- 作品库按"辑"折叠分组，卷首语（lead）显示概念；
- 编委**合并投稿时把新作 slug 拖进当期**即可（一行数据），GitHub 上操作 1 分钟；
- 首页与"雅集"区显示最新一卷入口。

### ⑥ "同时同期"概念化

诉求：同源作品不该只是干巴巴地列在一起，要有**概念叙述**（这场雅集是什么、主题、谁在唱和）。

**方案**：把 `source` 从"一个出处字符串"升级为**可挂概念卡的实体**：
- 新增 `src/_data/events.json`：每个雅集/同期一条：名称、时间、地点/线上、**辑语（概念性小序）**、主题意象、参与社员、关联作品 slug 列表；
- 作品页"同时同源"区块标题可直接链向该雅集的概念卡（独立小页或弹层），卡上有辑语与主题；
- 自动关联规则不变，但区块可以显示"同集 · 概念主题"而非纯列表。
