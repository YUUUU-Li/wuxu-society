## 二、机制（与讨论一致）

| 项 | 规则 |
|---|---|
| 权重 | **不加权**——关联度仍按标签向量的余弦归一，各类平权（讨论定：不用百分比权重） |
| 别名 | **不做自动吸附**——同义词由编委用「合并」动作处理（合并后票数并入目标词） |
| 自创标签 | 允许；表外词进"候选"，编委可采纳转正（进大纲）或合并/删除 |
| 限流 | **每设备每篇最多赞同 3 个标签**（取消不计数；服务端同时按 IP 兜底） |
| 手法类 | 与意象/情感/题材一样**开放给读者**（讨论定：开放） |

## 三、落库：以 SQL 为准（`sql/tags-v1/`）

**正式流程**（编委照做，手机端亦可）：

1. 打开 `sql/tags-v1/00-说明与预期数字.md`，按顺序逐条执行；
   - Cloudflare → D1 → `wuxu-database` → **Console**；
   - Cloudflare 控制台**一次只认一条语句**，所以**一个文件粘一次**，不要合并粘贴；
   - 每个文件里都写了「跑完应有的数字」，跑完对一眼（随时可跑 `10-核对-词数.sql`）；
2. 顺序：`01~04 落库四类词` → `05 候选转正` → `06/07/08 归并历史写法` → `09 索引（可选）` → `10/11 核对`；
3. 全部跑完的预期：**94 词全部「预设」**，表外自创候选保留，**读者票一张不丢**（见该文档表格）；
4. 命令行一次跑完亦可：`npx wrangler d1 execute wuxu-database --remote --file=sql/zhuzhu-tags-v1.sql`（同样幂等）。

**便捷等价入口**（应急/手机上顺手）：作品页 → 众注区右下「编委」→
- 「初始化/更新标签词表」≈ `01~05`、「整理历史标签」≈ `06~08`，两者都幂等、与 SQL 同源；
- 每个标签旁「⋯」：**采纳**（候选转正）/ **合并到某词**（票数并入）/ **删除**——这是 SQL 之外日常最常用的动作（SQL 只处理批量落库）。

> 一致性由 `scripts/test-tags-sql.js` 守住：SQL 里的词表、转正表、归并表必须与 `src/_data/tag_outline.json` 完全一致，否则 `npm test` 直接失败——**两份不会漂移**。

## 五、维护约定

1. 改词表（`src/_data/tag_outline.json`）→ `npm run sync-tags`（生成 Worker 用模块 `functions/api/tag-outline.js`）→ **同步 `sql/tags-v1/` 与 `sql/zhuzhu-tags-v1.sql` 的词表/转正表/归并表** → `npm test`（`test-tag-outline.js` + `test-tags-sql.js` 双重校验）→ 推送 → 编委按 §三 跑一次 SQL；
   手上只有 D1 控制台时，可整段粘贴 `sql/zhuzhu-tags-v1.sql`：94 词落库 + 历史写法归并（幂等，可反复执行）。
2. 新词先进"候选"，由编委按社内偏好定期转正（"若大家多用『爱』，就把『爱』加进大纲"）；
3. 不用为找相似作品而硬造标签——特别有特点的词也可以加，编委定期整理即可。
