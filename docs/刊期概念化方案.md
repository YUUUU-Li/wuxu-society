## 1. 两个核心概念

| 词 | 定义 | 例子 |
|---|---|---|
| **期（Issue）** | 一段**时间窗口**内收录的作品合辑——投稿攒够数、或一次雅集、或一个月，人工/自动"封期" | 《2026 年 9 月刊》《甲辰清明雅集》 |
| **概念（Concept）** | 跨期的**主题性**纽带——同题、同感、同意象群的"意义集合" | 「雨」「离别」「网络世代」 |

- **期**回答"这批作品是什么时候、以什么名义收进来的"（时间轴）；
- **概念**回答"哪些作品在精神上是一伙的"（谱系轴），也就是朋友说的"**同时同期的关联，最好有概念性**"——不只是同作者/同意象的机械推导，而是社里认可的"这一期共同在写什么"。

## 2. 数据结构草案：issues.json

新文件：`src/_data/issues.json`，每期一项：

```json
[
  {
    "id": "issue-2026-09",
    "title": "九月投稿辑",
    "vol": "第一卷",
    "no": "第一期",
    "type": "投稿辑 | 社课 | 雅集",
    "epigraph": "辑语（一句话点题，可空）",
    "window": { "from": "2026-09-01", "to": "2026-09-30" },
    "editor": "本期辑稿：jwl · 蓦流",
    "slugs": ["w-chenmo", "w-zhuyingtai", "…"],
    "preface": "optional-slug 或空（卷首语/序，见 §5）",
    "concepts": ["雨", "离别"]
  }
]
```

配套（可选、二期再做）：
- `concepts.json`：概念的"身份证"——`{ id, name, 小引(一两句题解), related: [概念 id] }`，
  让"概念"从**标签**升级为**可读的概念卡**（有题解、有谱系），而非光秃秃的筛选词；
- 每期一个正文页（生成静态页，URL 建议 `/issue-2026-09.html`）。

## 3. 与现有结构的关系（不推翻，只叠加）

| 现有物 | 关系 | 处理 |
|---|---|---|
| `groups.json`（作品库分组） | 是"页面上长期陈列"的抽屉 | 保持不动；可在其上方加一个"**刊期档案**"区（样式同首页"雅集档案"行式列表），点期名看当期目录 |
| `fulltext_order.json` | 全文库顺序 + 全站关联排序基准 | 保持为唯一"全库总序"；期只是它的**分组视图**，不改变总序 |
| 作品 `source` 字段 | 已承担"出处" | 老作品有出处的可**原样归入对应期**（如清明 7 篇 → 期"甲辰清明雅集"）；无出处的不硬造 |
| 首页"随机拾读" | 全库随机 | 不变；将来可加"**本期拾英**"视图，随机范围 = 最新一期的 slugs |

原则：**期是视图，不是新的全序**；一切排序仍以 `fulltext_order.json` 为唯一基准，避免双轨混乱。

## 4. 投稿"攒成一期"的操作流（给编委）

目标：朋友不需要懂 Git。理想闭环：

1. 投稿照旧走表单 → PR 审阅 → 合并发布（无改动）；
2. 合并时投稿函数自动给这篇记一个"**待封期**"标记（写到 `src/_data/pending_issue.json`：slug + 收录日期）；
3. **封期动作**（三个可选粒度，待拍板）：
   - 时间驱动：每月 1 号自动封上月（函数 + cron 或手动点一次按钮）；
   - 数量驱动：攒够 N 篇（如 5 篇）编委点"结一期"；
   - 事件驱动：某次雅集/社课结束后封期。
4. 封期生成物：`issues.json` 新条目 + 当期目录页 + （若选了卷首语）提示编委补一段辑语；
5. 展示：雅集页"刊期档案"出现新一期。

> 争议点：**自动封期**需要定时触发（Cloudflare Pages 无免费 cron；可用 GitHub Actions 每日检查，或投稿函数合并时顺带判断"本月窗口已到"）。草案默认走"**数量/事件驱动、编委一键封期**"，最省事也最符合社里节奏。

## 5. 期内容物的"文学格式"

一期不止是文件清单，按古籍"集"的体例可含：

- **卷首语/序**（可选）：一篇短文，说明本期缘起——可直接复用投稿的"序/自序"支持（P1 已给投稿加段首标记），也可由编委单独写；
- **辑语**：一句话题词（`epigraph`），展示在期页顶部，像《清明会序》之于首聚；
- **目录**：按收录顺序列题名/作者/体裁；
- **后记/编余**（可选）。

这让"期"成为**可读的小刊物**，而不是一个筛选标签——呼应"以文养心"的立社气质。

## 6. 概念页（概念化落地）

- 期里的 `concepts` 先指向现有意象标签或新概念 id；
- 概念化增强（阶段三）：生成 `/concepts/<id>.html`——页内有：概念名 + 一两句题解（社里人写，不用 AI 长文）+ 跨期作品列表 + 姊妹概念；
- 作品页的关联区可加第五组"**本期概念**"：显示该作所属期 + 概念卡链接，与 P0 的"同意象"区分开（意象=文本推导，概念=社里共识）。

## 7. 待拍板清单（开工前需定）

1. **期粒度**：自然月 / 攒够 N 篇 / 每次雅集后？（决定封期触发器）
2. **老作品归期**：45 篇旧作是否按"来源/雅集"补进历史期（如清明一辑、各分部雅集一辑），还是只从今往后算新刊？
3. **卷号体例**：要不要"第一卷 第一期"这种正式卷号，还是轻量"2026-09 辑"即可？
4. **卷首语**：每期是否都要序/辑语，还是选填？
5. **概念页范围**：先只把 `concepts` 挂意象标签跑通，还是单独建概念库？
6. 与 **P1 评论**的关系：期页要不要评论区（若 P1 选 Waline，期页与作品页共用即可，无额外成本）。
