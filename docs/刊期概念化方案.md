## 1. 两个核心概念

| 词 | 定义 | 例子 |
|---|---|---|
| **期（Issue）** | 一段**时间窗口**内收录的作品合辑——投稿攒够数、或一次雅集、或一个月，人工/自动"封期" | 《2026 年 9 月刊》《甲辰清明雅集》 |
| **概念（Concept）** | 跨期的**主题性**纽带——同题、同感、同意象群的"意义集合" | 「雨」「离别」「网络世代」 |

- **期**回答"这批作品是什么时候、以什么名义收进来的"（时间轴）；
- **概念**回答"哪些作品在精神上是一伙的"（谱系轴），也就是朋友说的"**同时同期的关联，最好有概念性**"——不只是同作者/相似标签的机械推导，而是社里认可的"这一期共同在写什么"。

## 2. 数据结构草案：issues.json

新文件：`src/_data/issues.json`，每期一项：

```json
[
  {
    "id": "issue-2026-09",
    "title": "九月投稿辑",
    "type": "投稿辑 | 雅集 | 文会",
    "period": "2026 年 9 月",
    "epigraph": "辑语（一句话点题，可空）",
    "slugs": ["w-chenmo", "w-zhuyingtai", "…"],
    "concepts": ["qingming", "lishe"]
  }
]
```

> 实际数据结构以 `src/_data/issues.json` 为准。早期草案里的 `vol`/`no`/`window`/`editor`/`preface` 未采用（卷号轻量化、辑语即 `epigraph`、卷首语直接作为一篇作品收入 `slugs`）。

配套（已实现）：
- `concepts.json`：概念的"身份证"——`{ id, name, note(一两句题解), related: [概念 id] }`，
  让"概念"从**标签**升级为**可读的概念卡**（有题解、有谱系），而非光秃秃的筛选词；
- 每期一个正文页（生成静态页，URL 建议 `/issue-2026-09.html`）。

## 3. 与现有结构的关系（不推翻，只叠加）

| 现有物 | 关系 | 处理 |
|---|---|---|
| `src/works/*.md` | 全站篇目、作品库平铺与全文库顺序的**唯一来源** | 构建期推导（`scripts/works-registry.js` + `scripts/work-order.js`）；期只是它的**分组视图**，不改变总序 |
| `src/_data/issues.json` | 期册：每期的 `slugs` 决定哪些作品已入期 | 散作 = 全站 − 已入期；封期脚本写这里 |
| 作品 front matter `pending: true` | 待辑标记 | 投稿函数写入，`seal-issue` 封期时清除 |
| 作品 `source` 字段 | 已承担"出处" | 老作品有出处的可**原样归入对应期**（如清明 7 篇 → 期"甲辰清明雅集"）；无出处的不硬造 |
| 首页"随机拾读" | 全库随机 | 不变；将来可加"**本期拾英**"视图，随机范围 = 最新一期的 slugs |

原则：**期是视图，不是新的全序**；一切排序仍以 `created`（`scripts/work-order.js`）为唯一基准，避免双轨混乱。

## 4. 投稿"攒成一期"的操作流（给编委）

目标：朋友不需要懂 Git。理想闭环：

1. 投稿照旧走表单 → PR 审阅 → 合并发布（无改动）；
2. 合并时投稿 PR 里的作品 front matter 带 `pending: true` 待辑标记（不再写任何共享 JSON）；
3. **封期动作**：由编委在合适时机一键 `npm run seal-issue`（事件驱动；已定案见 §7）；
4. 封期生成物：`issues.json` 新条目 + 当期目录页 + （若选了卷首语）提示编委补一段辑语；
5. 展示：雅集页"刊期档案"出现新一期。

> 争议点：**自动封期**需要定时触发（Cloudflare Pages 无免费 cron；可用 GitHub Actions 每日检查，或投稿函数合并时顺带判断"本月窗口已到"）。草案默认走"**数量/事件驱动、编委一键封期**"，最省事也最符合社里节奏。

## 5. 期内容物的"文学格式"

一期不止是文件清单，按古籍"集"的体例可含：

- **卷首语/序**（可选）：一篇短文，说明本期缘起——可直接用行首 `&` 排成楷体文段，也可作为一篇作品收入该期 `slugs`（清明期的社长序即此例）；
- **辑语**：一句话题词（`epigraph`），展示在期页顶部，像《清明会序》之于首聚；
- **目录**：按收录顺序列题名/作者/体裁；
- **后记/编余**（可选）。

这让"期"成为**可读的小刊物**，而不是一个筛选标签——呼应"以文养心"的立社气质。

## 6. 概念页（概念化落地）

- 期里的 `concepts` 指向 `concepts.json` 中已登记的概念 id；
- 概念化增强（阶段三）：生成 `/concepts/<id>.html`——页内有：概念名 + 一两句题解（社里人写，不用 AI 长文）+ 跨期作品列表 + 姊妹概念；
- 作品页的关联区可加第五组"**本期概念**"：显示该作所属期 + 概念卡链接，与"相似标签"区分开（相似标签=读者票推导，概念=社里共识）。

## 7. 已定案（原"待拍板"项，留档备查）

1. **期粒度**：事件驱动（雅集 / 文会 / 投稿辑），由编委确认后 `npm run seal-issue` 一键封期；不做自动定时封期。
2. **老作品归期**：按明确出处归入历史期——甲辰清明雅集 7 篇、回忆文会《时间溯流》9 篇、九月投稿辑 2 篇；其余散作留待攒期。
3. **卷号体例**：轻量 `period` 文本（如"2026 年 9 月"），不引入"第一卷第一期"。
4. **卷首语/辑语**：`epigraph` 选填；若有序文，直接作为一篇作品收入该期 `slugs`（清明期即此例）。
5. **概念页范围**：独立概念库（`concepts.json`），不把意象标签直接当概念；概念由期挂载，作品页与期页给入口。
6. **评论**：期页不单独接评论区；P1 众注自研（Cloudflare Pages + D1），作品页使用。
