# 网站投稿功能方案（方案①：网页投稿 → PR 审核 → 一键发布）

> 状态：**待实施**（代码未动，等 Netlify 侧配置就绪 + 确认开搭）
> 目标：让社员**只通过网页表单投稿**，编委在**网页预览**上审核，通过即自动上线；投稿人不需要 Git / Obsidian / GitHub。
> 仓库：<https://github.com/YUUUU-Li/wuxu-society> ｜ 站点：<https://wuxu-literary.netlify.app>

---

## 一、为什么需要这个方案

网站是 **Eleventy 静态站 + Netlify 托管**，页面本身没有服务器。要让"收稿 → 审核 → 发布"闭环，需要一个能存文件、能执行动作的"中间人"。最省事的中间人就是**仓库所在的 GitHub**：

- PR 合并 = 触发 Netlify 自动部署 = 新作上线（机制现成）；
- Netlify 会为每个 PR 自动生成**预览站**，审核人可以在真实版式里读投稿；
- 每个 PR 天然是一份投稿档案（谁投的、何时、通过/关闭）。

缺的只是一个"接线员"：一个极小的 **Netlify Function**，把网页表单转成一次自动 PR。

## 二、完整流程

```
投稿人（无需任何账号 / 不需要学 Git）
  │  打开网站 → 「投稿」页填表：题名 / 署名 / 体裁 / 正文 / 意象(可选)
  ▼
POST /api/submit  ← Netlify Function (netlify/functions/submit.mjs)
  │  ① 清洗校验：必填项、正文 ≤2 万字符、HTML 转义（防注入）、honeypot 防机器人
  │  ② 生成文件名：w-sub-<年月日时分秒>.md（中文题名不便拼音化，时间戳最稳；
  │     审核通过时可顺手改名）
  │  ③ 正文自动排版：按空行分段——
  │     体裁属 诗/词/联句/古风 → 段内行间加 <br />、class="stanza"
  │     散文/小说/序          → class="prose"
  │  ④ 拼出完整 .md（front matter + 正文）
  ▼
GitHub REST API（管理员 Token，见第三节）
  │  ⑤ 新建分支 submit/<slug>
  │  ⑥ 提交 src/works/<slug>.md，并把 slug 加进 src/_data/groups.json（"其余社员作品"组）
  │  ⑦ 开 PR：标题「投稿：<题名>（<署名>）」
  ▼
Netlify 自动为该 PR 生成【预览站】  ← 审核环节在这里
  ▼
编委/社长：打开预览链接通读 → 可在 PR 里直接微调 → GitHub 点 Merge
  ▼
自动部署 → 新作正式上线 ✔
（不通过：关掉 PR 并留言说明，投稿人可在网页重新提交修改稿）
```

## 三、仓库侧改动（开发者实施，预计一次完成）

| 文件 | 内容 |
|---|---|
| `src/submit.njk` | 投稿页表单（复用全站纸面样式与 head/导航/页脚 partial） |
| `src/index.njk` + 页脚 | 增加「投稿」入口 |
| `netlify/functions/submit.mjs` | 上述 ①–⑦ 全部逻辑（Node 18 内置 fetch，零第三方依赖，约 150 行） |
| `netlify.toml` | 确认 functions 目录声明（默认 `netlify/functions`） |
| `README.md` / 上传指南 | 补充"网页投稿"一节；Git/Obsidian 流程降级为审核人专用 |

## 四、需要 Netlify/GitHub 管理员配合的清单（一次性，约 15 分钟）

- [ ] **① 修正 Netlify 构建配置（最关键，也是新版上线的卡点）**
      旧配置指向已删除的 `wuxu-society/` 目录，导致新版一直未上线。
      Site configuration → Build & deploy → Build settings：
      - Base directory：**留空**
      - Build command：`npm run build`
      - Publish directory：`dist`
      （仓库根已有 `netlify.toml` 自带以上配置，Netlify 会自动读取；通常改完 Base directory 即触发重部署）
- [ ] **② 创建 GitHub Token**
      github.com → Settings → Developer settings → Fine-grained personal access tokens → Generate new token
      - Repository access：仅 `wuxu-society`
      - Permissions：**Contents: Read and write**、**Pull requests: Read and write**
      - 过期时间：建议 ≤ 12 个月，到期后重发
- [ ] **③ Token 存入 Netlify**
      Site configuration → Environment variables → 新增变量 `GITHUB_TOKEN_SUBMIT`，值粘贴上一步 token
      （函数代码只读取该环境变量，不进仓库；Token 只对本仓库有写权限，随时可吊销）
- [ ] **④ 确认 Functions 已启用**
      Netlify 免费档自带 Functions（12.5 万次/月调用），一般默认开启，无需付费；若 Site settings 里被关闭则打开
- [ ] **⑤（可选）替换占位邮箱**
      页脚 `wuxu.literature@example.com` → 真实社务邮箱（会出现在投稿页与页脚）

## 五、安全与成本

- **安全**：Token 仅存 Netlify 环境变量；权限限定单仓库 Contents/Pull requests；投稿正文按纯文本转义处理（不信任任何 HTML，无注入面）；匿名投稿 + honeypot + 长度上限 + 简易 IP 节流防垃圾。
- **成本**：零新增。Netlify 免费档：Functions 12.5 万次/月（投稿量远用不完）；PR 预览构建约 0.2 分钟/次（月 300 分钟，可支撑数百篇投稿）。GitHub 免费。
- **留痕**：每条投稿 = 一个 PR，天然形成审稿台账。

## 六、待确认事项
