# 网站自定义指南（想改什么 · 去哪改）

> 本文把本站**所有可自定义的地方**列成一张地图：改文字、改配色、改结构、改功能、改部署，
> 每一条都写明文件路径和注意点。适合维护者（你或朋友）对照操作。
>
> 配套文档：[编委操作手册](编委操作手册.md)（日常运维：审稿/封期/发布/测试）、
> [作品上传指南](作品上传指南.md)（给投稿人）、[域名接入指南](域名接入指南.md)、
> [网站精进方案](网站精进方案.md)（现状与路线）、[刊期概念化方案](刊期概念化方案.md)。

---

## 0. 全局概念：这个站是怎么拼出来的

```
md / json 内容  +  njk 模板(骨架)  +  site.css(皮)  +  site.js(动作)
        └────────── Eleventy 构建(npm run build) ──────────┘
                           └→  dist/ (纯静态 HTML)
                               └→ 推 GitHub main → Cloudflare Pages 自动发布(1-2 分钟)
```

- **改文字/内容**：多数情况只动 `src/works/*.md` 或 `src/_data/*.json`；
- **改布局/文案结构**：动 `src/*.njk`（页面级模板）与 `src/_includes/`（公共骨架）；
- **改样式**：`src/static/site.css`（唯一样式文件，内部有中文区块注释，可用 Ctrl+F 搜标题）；
- **改交互**：`src/static/site.js`（唯一脚本文件）；
- **改构建规则**：`.eleventy.js`；
- **改投稿后端**：`functions/api/submit.js`（入社申请为 `functions/api/join.js`）。

改完验证：`npm run build`（输出 `Wrote N files` 即成功）→ git 提交推送 → 等 1–2 分钟线上生效。

## 1. 站名、口号、站点地址（site.json）

文件：`src/_data/site.json`

| 字段 | 作用 | 例 |
|---|---|---|
| `name` | 站名（导航/页脚/标题默认用） | 婺需文学社 |
| `slogan` | 副题（浏览器标题默认后缀 + 各页 description 兜底） | 以诗会友，以文养心 |
| `url` | 站点正式地址（换域名后记得改这里） | https://wuxu.org |
| `footerNote` | 页脚注的全局默认（页面没写 footerNote 时用它） | 诗文录自社内原稿… |
| `wechat` | 公众号名片：`name`(名称)/`intro`(简介)/`qr`(二维码文件名，图放 `src/static/`，如 `wechat-qr.jpg`)；`name` 为空则首页与页脚不显示公众号入口 | 见 src/static/wechat-qr.jpg |

## 2. 作品内容（最常改的地方）

每个作品 = `src/works/<文件名>.md` 一个文件。**文件名就是网页地址**（如 `w-feng.md` → `/w-feng.html`），
改名永远安全（站内全部自动引用文件名），不要用中文/大写文件名。

### front matter（文件头 `---` 之间）可用字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 题名 |
| `author` | ✅ | 署名，如 `zk（道格）`——`（笔名）`会被自动拆成"缩写 + 笔名" |
| `genre` | ✅ | 体裁（决定正文排版 + 筛选项） |
| `imageries` | | 意象标签数组，如 `["雨", "清明"]`（决定"同意象"关联 + 筛选项） |
| `source` | | 出处/雅集，如 `清明雅集`（决定"同时同源"关联 + 筛选项） |
| `related` | | **唱和/组诗**等强关联：填对方文件名数组（可多篇） |
| `excerpt` | | 摘句（首页卡片缩略显示）；**留空自动取正文首句** |
| `fgenre` | | 列表/归档用的补充体裁说明（可选） |

> 其余字段（layout/permalink 等）已由 `src/works/works.11tydata.js` 自动生成，**不要手工写**。

### 正文里可用哪些"块"

正文是 HTML 片段，每段一个 `<p>`，段落种类（class）：

| 写法 | 效果 |
|---|---|
| `<p class="stanza">第一句<br />第二句</p>` | 诗句：行间自动断行 |
| `<p class="stanza kaiti">…</p>` | 楷体大段（自序/序文常用，见《芙蓉王诗》） |
| `<p class="prose">…</p>` | 散文段落 |
| `<p class="analysis">…</p>` | 赏析/评注块（自带分隔线样式） |
| `<p class="byline">…</p>` | 落款 |
| `<hr class="lib-hr" />` | 分隔线（长文分节用，见《文艺b与地雷女》） |

> 想换某篇的首页摘句：在 front matter 加 `excerpt: "你想要的句子"` 即可（不用改正文）。

## 3. 作品怎么"登记"才能进各列表

作品不只靠 md 文件，还要进**两份登记表**（都在 `src/_data/`）：

| 文件 | 作用 | 顺序即显示顺序 |
|---|---|---|
| `groups.json` | 作品库分组：数组每项 `{key, h2(组标题), slugs:[…]}` | 组顺序 = 页面顺序 |
| `fulltext_order.json` | 《全文源库》顺序 + **全站"关联作品"排序基准** | 数组元素为 slug |
| `concepts.json` | 概念档案：`{id, name, note(题解,可留空), related:[id]}`；某期 `issues.json` 的 `concepts` 填概念 id 后，自动生成概念页 `/concepts/<id>.html`，作品页与期页出现"本期概念"入口 | id 用拼音/英文 |

- **网页投稿**会自动登记这两份（见《编委操作手册》§5）；
- **手工新增作品**必须两个都登记，漏 `fulltext_order.json` 会进不了全文库/关联排序错乱。

## 3.5 作品排序与创作时间（`created`）

作品 front matter 支持 `created: "2024-04"`（或 `"2024-04-04"`）：

- **排序**：作品库平铺池、**库页各分组列表**、全文库页、关联作品组内，一律按 `created` **升序**（旧→新）；
- **展示**：作品详情页题下信息显示「创作时间 2024年3月6日」（`created` 为空则整条不显示）；
- **未填者**：继承前一篇已填作品的时点 —— 也就是保持现有编排位置不动，等你补填后自动归位；
- **补填工具**：`npm run set-created -- <slug> <YYYY-MM|YYYY-MM-DD> [...]`（支持 `--dry-run`）；
- **改名**：`npm run rename-work -- <旧slug> <新slug>` —— 文件名、五处登记、related 指向、名册链接、以及 `src/static/_redirects` 的 301 跳转一次改全（改完 `npm test` + 推送即可）；
- **归辑**：仍由编委人工封期（`npm run seal-issue`），创作时间用于期页/库内排序与封期时筛选参考；
- **旧的 `fulltext_order.json`**：仍保留为"登记表"（投稿函数与删稿脚本会维护它），但**展示顺序已由 `created` 推导**，手册顺序只作未填时间作品的相对次序。

## 4. 社员档案（members.json）

文件：`src/_data/members.json`——按分部（branch）分组的数组：
`{ branch, members: [{ id(缩写), name, role, branch, note(简介), links:[{href,label}] }] }`

- 新增社员：在自己分部数组里加一项；`id` 必须与作品 front matter 的 `author` 缩写一致，
  这样"作者 → 社员页"才能自动对应；
- **每人随机展示 3 首作品**：作品不再按名册 `links` 固定列出，而是页面加载时从作品库（`src/works/`）**随机抽 3 首**（每次打开可能不同，无"换一批"按钮）；名册 `links` 里的「作品：」条目仅作**无 JS / 搜索引擎回退**（静态先渲染前 3 条）；
- 库里作品多于 3 篇时，卡片底部出现「查看更多作品（共 N 篇）→」，指向作品库的作者筛选页（`library.html?author=…`，数字与链接由构建期索引自动生成）；
- 分部增减：直接改外层数组；页面标题/小标题若有硬编码需同步 `src/members.njk`。

## 5. 导航、页脚、各页头部

| 想改 | 文件 |
|---|---|
| 顶栏导航项（缘起/雅集/作品库/社员/投稿…） | `src/_includes/partials/nav.njk` |
| 移动端菜单开关文案/按钮 | 同上（`nav-toggle`）+ `site.css` 注释段「移动端导航」 |
| 页脚文字、备案号、"站点构建器"署名 | `src/_includes/partials/footer.njk` |
| 全站 <head>（标题规则/字体/图标） | `src/_includes/partials/head.njk` |
| 每页浏览器标签标题/描述/页脚注 | 各 `.njk` 页面文件的 front matter：`seoTitle`/`desc`/`footerNote` |

> 页脚最后一行 = 页面 `footerNote`（未设置时用 `src/_data/site.json` 的 `footerNote` 兜底）
> + 固定的授权链接（`LICENSE.txt` / `LICENSE-CODE.txt` 随站发布，UTF-8）。想改全局默认就改 `site.json`。

> 字体来自 Google Fonts（Noto Serif SC）——大陆偶有不稳属已知情况，换字体就在 head.njk 改。

## 6. 各功能页面的"区块文案"

每个页面一个模板文件（都在 `src/`），页面上的文字大多是**直接写在模板里**的，搜文字即可定位：

| 页面 | 文件 | 主要可改区块 |
|---|---|---|
| 首页 | `index.njk` | Hero 标题/副题、「申请入社」按钮、社训、缘起两段、雅集档案行、**同题作品 7 张卡片（静态）**、随机拾读引导语、入社表单文案/选项 |
| 作品库 | `library.njk` | 页头说明、筛选条标签 |
| 社员页 | `members.njk` | 页头说明 |
| 投稿页 | `submit.njk` | 表单字段（题名/署名/体裁/意象/出处/摘句/文件标识）、每字段的提示小字、成功提示文案 |
| 全文源库 | `_fulltext.njk` | 页头说明 |
| 每篇作品页 | `src/_includes/layouts/work.njk` | 元信息区、关联区标题（"同作者/同意象…"文案在各组标题，见 .eleventy.js） |

## 7. 样式与主题（site.css）

- 文件：`src/static/site.css`。**顶部 `:root{}` 是一站式换肤区**：

| 变量 | 含义 |
|---|---|
| `--paper` / `--paper-deep` | 页面底色 / 深一号纸色 |
| `--ink` / `--ink-soft` / `--dim` | 墨色文字三级（不要用纯黑） |
| `--line` / `--line-soft` | 分隔线透明度两级 |
| `--seal` | 印泥朱砂色（按钮/点缀） |
| `--maxw` | 内容区最大宽度 |

- 改任意细节：文件里有**中文分区注释**（Hero/宗旨横幅/作品库/移动端导航…），
  搜 `/* ---------- xxx ---------- */` 直达；
- 响应式断点集中在「响应式」区与文件末尾的媒体查询（≤960 / ≤640 两级）。

## 8. 页面行为与"轮换/随机"的可调参数

文件：`src/static/site.js`——各功能有中文注释：
- 滚动显现动画（`.rv`）；
- 移动端菜单开合（点外部/Esc 自动收起）；
- **关联作品轮换**：每次打开随机抽一批、「换一批」按钮；
- **首页"随机拾读"**：每次打开换 4 篇；
- 首页入社表单：**本站函数 `/api/join`**（提交后自动开 PR，申请书落在 `applications/`；本地预览无该接口，提交会失败属正常）；
- 作品库筛选（选项从行数据自动收集）。

轮换/随机数量的"源头"：
| 参数 | 在哪改 |
|---|---|
| 同作者每次显示几条（默认 5） | `.eleventy.js` 的 `ROTATE_MAX = { author: 5, imagery: 4 }` |
| 首页拾读每次几条（默认 4） | `index.njk` 随机拾读 `<script>` 里 `k < 4` 及 `homePool.slice(0, 4)` |
| 拾读池剔除哪些（默认立社同题 7 篇） | `.eleventy.js` 的 `FOUNDING` 数组 |
| 摘句长度上限 | `.eleventy.js` 的 `firstLine()`（34 字截断） |

## 9. 构建规则（.eleventy.js，进阶区）

- `addCollection("works")`：作品来源（`src/works/*.md`）；
- `addPassthroughCopy`：`src/static/` 原样复制（css/js/图片）；
- 过滤器：`akOf`（缩写）、`branchOf`（分部）、`relOf`（关联推导，含上限与排序）、
  `homeCards`（首页卡片池）、`worksMap`、`sortWork`；
- `firstLine()`：自动摘句逻辑（跳过行号行/短句）。

> ⚠️ 此文件与 `works.11tydata.js`、`functions/api/submit.js` 属于"底层"，
> 没把握前别乱动；改动后务必 `npm run build` 且逐页抽查。

## 10. 投稿 / 入社系统配置（functions/api/ + Cloudflare Pages）

| 想改 | 位置 |
|---|---|
| 投稿表单字段/提示 | `src/submit.njk` |
| 后端校验规则（长度/非法字符/限流）、正文自动排版（`bodyToHtml`）、front matter 生成 | `functions/api/submit.js` |
| 正文自动排版判据（哪些体裁算诗） | `submit.js` 顶部 `POETIC` 正则 |
| 段首标记（自序：/评：/注：） | `submit.js` 的 `P_KAITI` / `P_ANALYSIS` |
| GitHub Token（投稿/入社用它开 PR） | Cloudflare → Pages 项目 → Settings → Environment variables：`GITHUB_TOKEN_SUBMIT`（Encrypt） |

## 11. 部署与发布

- 构建命令 `npm run build`、输出目录 `dist` **在 Cloudflare 后台设置**（仓库内无配置文件，也就不存在后台覆盖仓库之说）；
- 发布链路：`git push origin main` → Cloudflare Pages 自动构建（1–2 分钟）；
- 函数目录：`functions/api/*.js`（CF 原生 ESM，路由 `/api/*`），勿与静态页同名。
- **换托管商**：迁往 Cloudflare Pages 的完整路线见《迁往CloudflarePages方案.md》——投稿函数已双平台化（`functions/submit.js` 适配器），只差账号侧操作；
- 本地预览：`python -m http.server 8124 --directory dist`，浏览器开 `http://127.0.0.1:8124`；
- 换域名：见《域名接入指南》，全站相对链接，无需改代码。

## 12. 版权与许可

- `LICENSE`（作品内容：CC BY-NC-ND 4.0）、`LICENSE-CODE`（代码：MIT）；
- 构建时两份许可会复制为 `LICENSE.txt` / `LICENSE-CODE.txt` 随站发布（UTF-8 BOM），页脚授权行可点开；

### 快速自查清单（改完任何东西）

1. `npm run build` 无报错、Wrote 数量正常；
2. 涉及登记表：确认 slug 在 `groups.json` 与 `fulltext_order.json` 都存在且不重复；
3. 涉及页面：本地预览翻一遍（尤其手机宽度）；
4. git 推送后等 1–2 分钟，用无痕窗口验证线上。
