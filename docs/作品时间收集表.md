## 一、怎么补填

1. 与作者或编委核对到**年、月**即可（知道具体日子更好）。日期写法很随意，脚本会统一归一化：
   `20240911` · `2024.9.11` · `2024/9/11` · `2024年9月11日` · `2024-09-11`（到日）；`202409` · `2024-09`（只到月）；`2024`（只到年）；
2. 写进 front matter：
   ```bash
   npm run set-created -- w-mei 2024-05 w-feng 2024-06 --dry-run   # 先看改动
   npm run set-created -- w-mei 2024-05 w-feng 20240605           # 8 位/点号写法也认
   npm test && git add -A && git commit -m "补创作时间" && git push
   ```
3. 排序口径（单一真相在 `scripts/work-order.js`）：`created` **升序**（早者在前）；
   **模糊的往前排**——只知月份的排在该月有具体日子的**前面**（`2024-06` 在 `2024-06-07` 之前，`2024` 在 `2024-06` 之前）；
   **未填者不猜日期**——统一排在已填者之后，作品库里另立「年份待考」一节（组内保持 `fulltext_order.json` 原次序）。
   ⚠️ 旧口径是「未填者继承前一篇已填作品的时点」：因 `fulltext_order.json` 开头就是 2024-04-04 的清明雅集，
   30 多篇未填作品会被一律算作 2024-04-04（含 2026 年的投稿）挤作一堆，故已废弃。
