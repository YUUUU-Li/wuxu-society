# 作品上传指南（给社员）

> 目标：**一篇作品从写到上线**，全程约 10 分钟。适合完全没接触过 Git 的同学。
> 仓库：<https://github.com/YUUUU-Li/wuxu-society> ｜ 网站：<https://wuxu-literary.netlify.app>

---

## 一、总流程（先记住这一句）

**写 md → 放进 `src/works/` → 在 `src/_data/groups.json` 登记 → git 提交推送 → 网站自动更新**

本仓库是"数据 + 模板"结构：每篇作品只是一个 Markdown 文件，网页、作品库列表、同作者/同意象/同时同源等关联页面全部由构建器**自动生成**，不需要也不会去手改 HTML。

---

## 二、第一次：准备环境（一次性）

### 1. 装两个软件
- **Git**（Windows 装 [Git for Windows](https://git-scm.com/download/win)，装完桌面/开始菜单有 "Git Bash"）
- **Node.js**（[nodejs.org](https://nodejs.org) 装 LTS 版）

### 2. 把仓库拉下来
打开 **Git Bash**，输入：

```bash
git clone https://github.com/YUUUU-Li/wuxu-society.git
cd wuxu-society
npm install        # 首次安装构建工具，跑一次即可
```

> 国内网络提示：如果 clone 或 push 卡住/超时，先给 Git 配上代理（你电脑上已有的 7890 端口代理）：
> ```bash
> git config --global http.https://github.com.proxy http://127.0.0.1:7890
> ```
> 配一次即可，以后所有 GitHub 操作自动走代理。

### 3. 用 Obsidian 打开这个仓库（推荐）
Obsidian 本身就是一个 Markdown 编辑器，直接把它当"写作台"：

1. Obsidian → **打开其他仓库** → **打开文件夹作为仓库** → 选中刚 clone 的 `wuxu-society` 文件夹；
2. 设置 → 文件与链接 → **忽略的文件** 填：`node_modules, dist, .git`（让 Obsidian 不去索引这些构建产物，可选但建议）；
3. 平时写作只碰 `src/works/` 里的 `.md` 文件；
4. 编辑时把右上角切换到**源码模式**（正文是 HTML 片段，不是普通预览）。

> 不想用 Obsidian 也行：记事本、VS Code、Typora、GitHub 网页在线编辑都可以，规则一样。

## 三、写一篇新作品

### 1. 复制一个模板文件
打开 `src/works/`，复制 `w-feng.md`，重命名为你的作品文件。**文件名 = 网页地址**，规则：小写字母 + 连字符，不要空格/中文。例如：

- zk 的五绝《忆征人》→ `w-yizhengren.md`（沿用旧例）
- 新作示例：`w-qiuwang.md`（秋望）、`w-chunye.md`（春夜）

> 旧站沿用两套前缀：立社雅集作品 `qingming-*.md`，其余 `w-*.md`。日常新作一律用 `w-` 前缀即可。

### 2. 填文件头（front matter）
`---` 之间的内容是作品"身份证"，Obsidian 里会显示成属性面板。**只需填这几项**：

```yaml
---
title: "秋望"
author: "zk（道格）"
genre: "五律"
imageries: ["秋", "思乡归途"]
source: "癸卯秋社课"
---
```

| 字段 | 含义 | 示例 | 必填？ |
|---|---|---|---|
| `title` | 题名 | 秋望 | ✅ |
| `author` | 署名：姓名缩写（笔名）。新社员先让社长把缩写+笔名+分部加进 `src/_data/members.json` | `zk（道格）`；无笔名就写 `cty` | ✅ |
| `genre` | 体裁 | 七律 / 词 / 现代诗 / 散文 / 短篇 | ✅ |
| `imageries` | 意象标签，列表形式 | `["秋", "思乡归途"]` | 推荐 |
| `source` | 出处/雅集名。**有它**，同出处作品会自动互链成"同时同源" | `甲辰清明首聚（2024.4.4）` | 选填 |
| `related` | 仅"唱和/组诗"这类人工关系才填（见下） | 见示例 | 选填 |
| `fgenre` | 全文库展示用体裁，极少数需要 | `词 · 附赏析` | 选填 |

**不用填**（构建器自动处理）：页面文件名、SEO 标题/描述、分部、缩写锚点、同作者/同意象/同时同源关联。

### 3. 填正文（`---` 之后）
正文是 HTML 片段，**每段一个 `<p>`，改字只动这里**：

```html
<!-- 正文片段: 每段一个 <p>；改字请只动这里 -->
<p class="prose">散文或前言段落，直接写文字即可。</p>

<p class="stanza">律诗/绝句/词的句子，每句一行，句间用 &lt;br /&gt;：<br />
万里悲秋常作客，百年多病独登台。<br />
艰难苦恨繁霜鬓，潦倒新停浊酒杯。</p>

<p class="analysis">赏析、评注（可选）。</p>

<p class="byline">落款，如：zk 记于癸卯秋分</p>
```

段落类型对照：

| class | 用途 | 样式 |
|---|---|---|
| `prose` | 散文/小说正文 | 常规小字 |
| `stanza` | 诗句段（行间用 `<br />`） | 大字号诗句 |
| `stanza kaiti` | 楷体诗句（手书感） | 楷体 |
| `analysis` | 赏析/评注 | 带分隔线的小字 |
| `byline` | 文末落款 | 右对齐 |

### 4. 唱和/组诗怎么标（唯一的"人工关联"）
同作者、同意象、同时同源会自动算。**只有"谁和答谁、谁与谁同题"这种创作关系**需要手动补一条 `related`：

```yaml
---
title: "忆秦娥·和答蓦流《小重山》"
author: "lfk（谰予）"
genre: "词"
source: "公众号回忆文会《时间溯流》"
imageries: ["秋", "离别相思"]
related:
  - to: "w-xiaochongshan"
    label: "唱和 · 和答蓦流《小重山》"
---
```

`to` 填对方作品的文件名（不含 `.md`），`label` 写一句关系说明。它会显示在"本作关联（唱和 · 组诗）"分组里。

## 四、登记到作品库

打开 `src/_data/groups.json`，把**文件名（不含 `.md`）**加进合适分组的 `slugs` 数组末尾：

```json
{
  "key": "other",
  "h2": "其余社员作品",
  "slugs": [ "…", "…", "w-qiuwang" ]
}
```

三个分组：`qingming`（清明首聚·立社原创）、`huiyi`（回忆文会《时间溯流》）、`other`（其余社员作品）。日常新作放 `other` 即可；忘登记的话作品页能生成但作品库列表里找不到。

## 六、提交并推送（每次改完都做这 4 步）

回到 **Git Bash**（在 `wuxu-society` 目录下）：

```bash
git pull                 # ① 动手前/提交前先拉最新，避免和别人冲突
git add src/works/w-qiuwang.md src/_data/groups.json
git commit -m "新增 zk 五律《秋望》"
git push                 # ② 推送到 GitHub
```

几点习惯：
- `git add` 只加你改过的文件（上面示例），也可 `git add .` 一把梭（会把你仓库里所有改动都带上）；
- 提交说明（`-m` 后面）写清楚干了什么：新增/改字/删稿，例：`fix: 修正《风》第二句错字`；
- **先 pull 再动手**能少很多麻烦；如果 push 被拒（别人先推了），执行 `git pull --rebase` 后再 push；
- 想确认改了啥：`git status`（红色=改了没加，绿色=加了没提交）。

推送成功后等 1–3 分钟，打开 <https://wuxu-literary.netlify.app> 就能看到新作（Netlify 自动构建部署，无需手动操作；首次由仓库管理员确认构建配置即可）。

## 七、最懒方案：不用装任何东西，GitHub 网页直接改

1. 浏览器打开仓库页面 → 进 `src/works/` → 点 **Add file → Create new file**；
2. 文件名写 `w-qiuwang.md`，把模板内容（front matter + 正文）粘贴进去改好；
3. 顺手把文件名加进 `src/_data/groups.json`（点文件 → 铅笔编辑 → 改完 Commit changes）；
4. 填个提交说明，点 **Commit changes**。

GitHub 网页会直接显示 Markdown 渲染效果，手机也能操作。适合偶尔投一篇稿的同学。

## 八、常见问题

| 现象 | 原因/解法 |
|---|---|
| 作品库列表里没有我的新作 | 忘了在 `groups.json` 登记 → 补上后重新 commit/push |
| 点进去 404 | `groups.json` 里写的 slug 与文件名不一致（必须完全一样、小写） |
| 页面上作者/分部不对 | 找社长更新 `members.json`，再在 md 里用正确的缩写署名 |
| 想改错字 | 直接改 md 正文 → `git add` → `git commit -m "fix: 改字"` → `git push` |
| 改坏了想还原 | `git restore src/works/xxx.md`（未提交时）；已提交可找我帮忙回退 |
| push 被拒 | 别人先推了 → `git pull --rebase` 再 `git push` |
| 删除一篇作品 | 删 md + 从 `groups.json` 移除 slug，然后照常提交推送 |
| 想写草稿/随笔又不想上线 | 放仓库外的文件夹（如你自己的 Obsidian 主 vault），定稿后再复制进来 |

## 九、Obsidian 写作小贴士

- 可以装社区插件 **Templates**，做一个"作品模板"，新作一键套用文件头：
  ```markdown
  ---
  title: ""
  author: ""
  genre: ""
  imageries: []
  ---
  ```
- `---` 之间的字段 Obsidian 会自动识别为**属性**（右上角属性面板可改，效果等同手写 YAML）；
- 正文请用**源码模式**编写（`Ctrl/Cmd + E` 切换），预览模式里 HTML 片段不会完整显示；
- 仓库内 md 之间的关联是普通网页链接，不需要 Obsidian 的 `[[双链]]`；个人阅读笔记想用双链请放在仓库外的 vault；
- 别在仓库里随手建草稿文件：构建只认 `src/works/`，但多余文件会被 push 到 GitHub，保持仓库干净。
