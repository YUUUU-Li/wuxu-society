# 编委操作手册（日常运维 · 一篇就够）

> 给维护网站的你/朋友：从"审一篇投稿"到"攒一期、发一版"的日常操作都在这里。
> 配套文档：《网站自定义指南》（想改哪去哪改）、《域名接入指南》、《作品上传指南》（给投稿人）。
> 术语约定：**投稿=网页表单来稿**；**封期=把一批来稿攒成"一期"**；**发布=代码推送到 GitHub main，Cloudflare Pages 自动上线**。

---

## 0. 一分钟速览

| 想做什么 | 用什么 |
|---|---|
| 看最新效果 | 本地预览（见 §1） |
| 审一篇投稿 | GitHub 打开 PR → 检查 → Merge（§2） |
| 把投稿攒成"一期" | `npm run seal-issue`（§3） |
| 撤一篇已上线的稿 | `npm run remove-work w-xxx`（§2.5） |
| 让改动上线 | `git push`（§4） |
| 检查有没有改坏 | `npm test`（§1） |

> Git 命令都需走代理（大陆直连 GitHub 超时）：
> `git -c http.proxy=http://127.0.0.1:7890 -c http.sslBackend=openssl <命令>`

## 1. 构建 / 测试 / 本地预览

```bash
cd D:/wuxu-society          # 或你的仓库目录
npm run build               # 重新构建 dist/（改任何东西后先跑它）
npm test                    # 全量回归：构建 + 投稿函数测试 + 站点断言（绿=放心）
python -m http.server 8124 --directory dist   # 起本地预览
# 浏览器开 http://127.0.0.1:8124 ；手机同 Wi-Fi 可用 http://电脑IP:8124
```

- 改动**任何**模板/脚本/数据后，都跑一遍 `npm test`，全绿再提交；
- 本地预览里"投稿提交、入社表单"会失败属正常（那是线上功能）。

## 2. 审核一篇投稿（核心流程）

投稿者在网页填表后，会自动开一个 GitHub PR（标题「投稿：题名（署名）」）。

1. 打开仓库 [YUUUU-Li/wuxu-society](https://github.com/YUUUU-Li/wuxu-society) → **Pull requests** → 点开最新一条；
2. **先看正文**：
   - 开头是作品信息（题名/作者/体裁/出处），另有 **题记** / **自注**（投稿者填的话，会把楷体排在作品开篇与正文下方，**会发布**）；
   - 若有 **「给编委的附言」**（引用块）——投稿者想说的话（第几稿、是否匿名等），**只看不发布**；
3. **看 Files changed**（改动文件）：
   - `src/works/w-xxx.md` 是作品正文；
   - 投稿 PR **只新增一个作品文件**（`src/works/w-<日期>-NN.md`，front matter 带 `pending: true` 待辑标记）——**不再修改任何共享登记表**，所以多份投稿可以同时挂着、任意顺序依次合并，不会互相冲突；
   - 名单（全站篇目 / 已入期 / 散作 / 待辑）都是构建期从作品目录推导的，见 `scripts/works-registry.js`；
4. 想改文字：直接在该 PR 的 Files changed 里点 ✏️ 编辑，改完 Commit；
   - 想给作品一个短文件名（投稿时没填文件标识的话是时间戳名）：编辑提交时把 **文件名** 也改成 `w-拼音.md`，全站自动生效（无引用依赖）；
5. 满意后点 **Merge pull request** → Confirm。**合并即发布**（Cloudflare 自动构建，1–2 分钟上线）；
6. 线上验收：打开作品页（新页 URL）确认渲染正常。

要点：
- **只有有仓库写权限的人（你和朋友）能 Merge**；路人只能评论；
- 明显是垃圾/测试稿 → 直接 **Close pull request**（不合并即不发布）；
- 投稿 PR 内容公开可见（仓库是 public），投稿者的敏感附言请勿外传。

### 2.4 在 GitHub Desktop 里看稿（Desktop 只能"看"，批准要去网页）

⚠️ GitHub Desktop **没有**评论/审核/合并按钮（[官方文档](https://docs.github.com/zh/desktop/working-with-your-remote-repository-on-github-or-github-enterprise/viewing-a-pull-request-in-github-desktop)：要评论、审核或合并拉取请求，需转到 GitHub 上的 PR 页面）。Desktop 的长处是"把稿子拉到本地通读、顺手改"：

1. 顶部点 **Fetch origin** 刷新（新投稿是个远端分支 `submit/w-xxxx`，不刷新看不到）；
2. 点左上 **Current Branch** → 切到 **Pull Requests** 标签（列表右上 ⟳ 可刷新）→ 点那条「投稿：题名（署名）」；
   - 这一步只是把该分支**检出到本地**（不动 `main`，随时能切回来）；
3. 左侧 **History**：把"选择用于比较的分支"填成 `main`，看 **Ahead** 有几个提交；或直接看 **Changes** 里改动的文件；
4. 想改稿：**Repository → Open in editor**（或直接用 Obsidian 打开这个仓库）改 `src/works/w-xxxx.md`，改完 commit + **Push origin**（推到那个分支，PR 会自动更新，Cloudflare 预览链接也会刷新）；
5. **批准/合并回网页**：菜单 **Branch → View pull request on GitHub**（或 PR 页直接点 **Merge pull request** → **Confirm merge**，随后可 **Delete branch**）；
6. 合并后 1–2 分钟自动上线 → 打开作品页核对。

> 更省事的路径：投稿成功后页面会给出「**查看审稿单（需 GitHub 登录）**」直链；把 <https://github.com/YUUUU-Li/wuxu-society/pulls> 收藏起来也行——仓库是 public，**只读浏览不用登录，但合并必须用有写权限的账号**。
> 也可以让 Agent 先把该 PR 里的稿子内容抓下来给你复核（仓库 public，Agent 可读不可写）。

### 2.5 撤稿 / 下架（误合入、内容问题需删除）

撤稿一键脚本（作品名只记在作品文件与 `issues.json` 期册里，脚本会一起处理）：

```bash
npm run remove-work -- --dry-run w-sub-xxx   # 先预览会删哪些（不写盘）
npm run remove-work w-sub-xxx                 # 正式下架（w-sub-xxx 换成真实 slug，见作品库 URL）
```

自动完成：删除 `src/works/w-xxx.md`；若该篇已入期，同时从 `src/_data/issues.json` 摘除该 slug → 全站（库/期/首页拾读/筛选/sitemap/概念收录）一起消失。脚本会打印提交命令，照跑 push 即上线。

> 该脚本也适用于"撤下已入期的旧作"（同样会从对应期页摘除）。
> git 历史仍保留该稿，需要找回可 revert 本次提交。
> `npm test` 内置一致性检查：期册里的 slug 必须有对应作品文件、同一 slug 不得重复登记、已入期 + 散作必须等于全站篇目（漏改会直接报错）。

## 3. 封期（把来稿攒成一期）

新投稿合并后会自动进入"待辑"状态（**雅集页**"刊期档案"标题下有朱砂提示"N 篇待辑"）。攒够了就封一期：

```bash
npm run seal-issue -- --dry-run          # 先预览将生成的新期（不写盘）
npm run seal-issue                        # 正式封期：默认"YYYY-MM 投稿辑"
# 自定义：npm run seal-issue -- --title "癸卯冬辑" --type 雅集 --period "2026 年 11 月" --epigraph "一句辑语。"
# 同月第二次封期需加 --id：npm run seal-issue -- --id issue-2026-11-2
```

脚本自动完成：待辑篇目 → `issues.json` 新期 → 从"散作"组移出 → 清空待辑 → 打印提交命令。照打印执行：

```bash
git add src/_data/issues.json src/works
git -c core.autocrlf=false commit -m "feat(刊期): 封期 …"
git -c http.proxy=http://127.0.0.1:7890 -c http.sslBackend=openssl push origin main
```

上线后：**雅集页**（`yaji.html`）"刊期档案"多出新一期页 `/issue-xxx.html`。

手工微调期：直接编辑 `src/_data/issues.json`（改标题/辑语/收录篇目都行，改完照 §4 提交）。

## 4. 发布任何改动（含文档）

```bash
git add -A
git -c core.autocrlf=false commit -m "说明：做了什么"
git -c http.proxy=http://127.0.0.1:7890 -c http.sslBackend=openssl push origin main
```

- push 即自动部署（Cloudflare Pages，连接 GitHub 自动构建，1–2 分钟）；**等 1–2 分钟后**刷新线上验证（用无痕窗口避免缓存）；
- 若线上迟迟不变：Cloudflare → Workers & Pages → 项目 → **Deployments** 看最近构建是否成功/Failed（贴错误信息求助），成功后可点 **Retry deployment**；
- ⚠️ 静态站构建设置在 **Cloudflare 后台**（Build command=`npm run build` / Output=`dist`）；投稿函数在 **`functions/api/submit.js`**（CF Functions 目录须在 Settings→Functions 确认 `/functions`），环境变量 `GITHUB_TOKEN_SUBMIT` 在 CF 后台配置；
- 线上由 Cloudflare Pages 托管（Git 连本仓库 main，push 即自动构建发布，约 1–2 分钟）。

## 5. 日常改内容（不写代码）

| 想改 | 位置（详见《网站自定义指南》） |
|---|---|
| 某一篇作品文字 | `src/works/w-xxx.md`（正文为 HTML 段落；改完 §1/§4） |
| 首页摘句 | 该作品 front matter 加 `excerpt: "…"` |
| 题记 / 自注（楷体排开篇、正文下方） | 该作品 front matter 加 `epigraph: "…"` / `selfNote: "…"`（换行写 `\n`） |
| 一篇新作品直接入库（不走网页投稿） | 新建 `src/works/w-xxx.md` 即可（`created` 决定排序）；若属某期则再加进 `issues.json` 对应期。**无需任何登记表** |
| 公众号名片/二维码 | `src/_data/site.json` 的 `wechat` + `src/static/wechat-qr.jpg` |
| 页脚注/版权行 | 各页 front matter `footerNote`；全局默认在 `site.json.footerNote` |
| 社员档案 | `src/_data/members.json` |

## 6. 后台与凭据（需登录 Cloudflare / GitHub）

- **投稿函数钥匙**：Cloudflare → Pages 项目 → Settings → Environment variables 的 `GITHUB_TOKEN_SUBMIT`。
  它等同"仓库写权限"，**只在 CF 后台存放，别公开/别外发**；怀疑泄露就让 GitHub 后台吊销重建后 CF 更新；
- **入社申请**：投递后自动开 PR，内含 **两份改动**：① 申请书 `applications/*.md`（不进构建）；② **名册草稿** `src/_data/members.json`（缩写建议取邮箱前缀、分部取"地区"字段（未填记「待考」）、角色默认「社员」）。
  **编委只需在 PR 里把草稿条目改妥**（缩写、分部、角色、姓名格式 `缩写 · 笔名`），点 **Merge 即同时完成归档与入册**，社员页随之更新。
  漏改或事后补录：`npm run add-member -- <缩写> <笔名> [--branch 分部] [--role 角色] [--note "简介"] [--note-link w-xxx.html:评注：xxx]`（含单测，`npm test` 覆盖）。名册**不再登记作品链接**——卡片作品由作品池自动随机抽取；`--note-link` 只用于编委想手写的交叉链接。
- **标签大纲与采纳**：词表见《标签大纲.md》（94 词 · `src/_data/tag_outline.json`）。改词表后跑 `npm run sync-tags`；改**名册**（`members.json`）后跑 `npm run sync-zhuzhu`（把社员缩写/笔名编译成"保留昵称"，防游客抢注）；两者都记得 `npm test` 再推送。**编委身份用账号**（`users.role='编委'`：登录后每词旁出现「⋯」、每楼出现「删」）；旧的共享钥匙 `ZHUI_ADMIN_KEY` 过渡期仍可用。手上只有 D1 控制台时，也可逐条粘 `sql/tags-v1/…`（与按钮等价，幂等）。
  标签旁「⋯」可**采纳**（自创候选转正）/ **合并到某词**（票数并入，解决"恋慕 vs 爱"这类同义分散）/ **删除**。每个设备每篇最多赞同 3 个标签（防跟风）。
- **编委删除评论**：作品页众注区右下角小字「**编委**」。**用编委账号登录后管理入口自动开启**（按钮显示「编委（账号）」，无需钥匙）；若仍用旧的共享钥匙，点它输入钥匙亦可开启（钥匙只存浏览器会话、不进网址）。
  - 钥匙是 Cloudflare 环境变量 `ZHUI_ADMIN_KEY`（**未配置则该入口无效**，返回"无权删除"）；
  - 删除为**软删除**（库里保留 `deleted_at`，读者端即刻不可见），符合"先显后删"原则；被回复的楼删除后，回复标识显示「**该楼已删**」占位（不可点击跳转）；
  - 退出编委模式：再点一次「退出编委」；换浏览器需重新输入。
- **作品改名（在哪里跑、怎么跑）**：命令在你**自己的电脑上、仓库目录里**用终端执行（git-bash / PowerShell / VS Code 终端均可），不是 CF 后台、也不是 GitHub 网页。
  1. **合并前改**（推荐，网址一开始就是雅名）：
     ```bash
     git fetch origin submit/w-2024-0404-01
     git switch submit/w-2024-0404-01
     npm run rename-work -- w-2024-0404-01 zhuyingtai --dry-run   # 先看改动清单
     npm run rename-work -- w-2024-0404-01 zhuyingtai            # 真执行
     npm test && git commit -am "rename: w-2024-0404-01 -> zhuyingtai" && git push
     ```
     回 GitHub 刷新该 PR，文件已换成新名，再 Merge 即上线。
  2. **合并后改**（也能用）：在 main 上同样跑 `npm run rename-work -- <旧> <新>` → `npm test` → 提交推送。
  两种情形该脚本都会**自动往 `src/static/_redirects` 追加一条 301**，旧网址自动跳新网址（已分享出去的链接不会失效）。
- **回填创作时间**：`npm run set-created -- <slug> <日期> [...]`（可多组一次写，支持 `--dry-run`）。日期写法随意——`20240911` / `2024.9.11` / `2024年9月11日` / `2024-09-11`（到日）、`202409` / `2024-09` / `2024.9`（只到月）、`2024`（只到年），脚本统一归一化后写入。排序 = 创作时间**升序**，且**模糊的往前排**（只到月的排在当月具体日子之前，只到年的排在该年各月之前）；**未填者不猜日期**、统一排在已填者之后（作品库底部「年份待考」一节），补填后自动归位；缺哪些、属哪一批见 `docs/作品时间收集表.md`（重跑 `node scripts/work-dates-report.js` 刷新）。口径单一真相在 `scripts/work-order.js`（单测 `scripts/test-dates.js`）。
- **GitHub 审稿**：仓库 Pull requests 列表；有写权限的协作者可 Merge。

## 7. 常见问题速查

| 现象 | 排查 |
|---|---|
| 线上还是旧版 | 等 1–2 分钟 → Cloudflare Deployments 看是否失败/未触发 → Retry deployment |
| 投稿提交后没反应/报错 | 看函数是否注册（线上 `/api/submit` GET 应 405）；token 是否在 CF env |
| 页面字体/图挂了 | 仓库 `src/static/` 文件是否在、路径是否写对 |
| LICENSE 中文乱码 | 已修（构建加 UTF-8 BOM）；仍乱码则把浏览器缓存清了 |
| 本地预览打不开 | 先 `npm run build`，确认 8124 端口未被占用 |
| push 报 SSL 握手失败 | 命令加 `-c http.sslBackend=openssl`；代理没开会报连不上 7890 |
| 想撤掉刚提交的改动 | `git reset --soft HEAD~1`（改错后未 push 时用） |
