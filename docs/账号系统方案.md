# 账号系统方案（轻身份 · P1）

> 状态：**待社内确认后实施**。目标只有一句话：**让每一张标签票、每一条评论都有明确归属**，同时又不用背上"真账号"（邮箱/手机/验证码）的负担。
> 相关：`sql/accounts/`（建表脚本）、`sql/curation/`（清库脚本）、`sql/backup/`（改造前数据快照）。

## 一、为什么要做（把我们踩过的坑记在这里，免得以后重复）

设备号/IP 身份带来四个必然问题：

1. **换设备即失联**：清了缓存、换浏览器、用无痕，之前投的票就"不是你的"了（不高亮、不能取消）；
2. **共用设备混淆**：一台电脑两个人用 → 被当成同一个人（共用 3 票额度）；
3. **老 IP 票无主**：早期按 IP 存的票，永远算不出是谁投的，只能"只计数、不认人"；
4. **口径不一致**：红/灰、3 票上限、取消三处各查各的键，于是出现过"页面全灰却说已达上限"这种死锁。

**结论：互动一律要求登录，浏览不用登录。**
- 需要登录：打标签（赞同/取消）、发表评论、评论同感；
- 不需要登录：读作品、看标签计数、看评论、作品库筛选、投稿（投稿本来就走 PR 审核）。

## 二、身份模型

| 角色 | 登录名 handle | 显示笔名 nick | 权限 |
|---|---|---|---|
| **读者**（游客/非社员） | 自拟（不得与社员缩写/笔名重名） | 自拟 | 打标签、评论、同感 |
| **社员** | 名字缩写或笔名（如 `jwl`、`蓦流`） | 笔名（如「蓦流」） | 同读者；注册后可被编委确认身份 |
| **编委** | 本人缩写 | 笔名 | 同社员 + 管理：确认社员、开号、删评论、整理标签（**取代共享钥匙 `ZHUI_ADMIN_KEY`**） |

### 社员怎么认（不设邀请码，靠编委确认）

注册页加一个勾选框「**我是社员**」：

- **勾选**：登录名/笔名输入框提示「**请用名字缩写或笔名**」；
- **未勾选**：提示「**推荐使用名字缩写或笔名**」（游客也可用自拟名）；
- 无论勾不勾，**唯一性与保留名单校验都同样执行**（见第三节）；
- **勾选 ≠ 立即成为社员**：账号创建为「**待确认**」（`users.member_state='待确认'`，角色仍是读者），编委在后台核对缩写后点一下「确认社员」才转为社员。
  > 这样社员零障碍，冒充者最多只能拿到一个"待确认"状态，编委不确认就没有社员身份。

## 三、命名与保留规则

1. **`handle`（登录名）唯一**、**`nick`（显示名）也必须唯一**——否则评论区会出现两个「蓦流」，无法辨认；
2. 校验前先**归一化**：去掉首尾与中间空白、忽略大小写、全角转半角、去掉 `·`/`（）` 等分隔符后比对；
3. **保留名单**由名册自动生成：`src/_data/members.json` 里的 `id`（缩写）+ `name` 中 `·` 之后的笔名 + 括号里的别名。
   例如现有社员会保留：`jwl 蓦流 cty 泊珩 cyk 昱白 cyly wxh lrz hhy 渔歌 lfk 谰予 ylj 济枫 hde 新酒 Hugo zk 道格 txy 飞鸟 lys wzx`；
4. 生成方式与标签词表同一套路（Workers 里没有文件系统，词表须编译进函数）：
   `scripts/sync-members.js` → 生成 `functions/api/members-reserved.js`；名册有变动就重跑并 `npm test`；
5. **提示文案**（前端给体验，服务端必须再校验一遍）：

| 情况 | 提示 |
|---|---|
| 撞上保留名单（属社员的缩写/笔名） | **该昵称已被占用（属社员），请换一个；若你是本人，请联系编委开号** |
| 撞上已注册账号 | **该昵称已被占用，请修改昵称** |
| 其余合法 | 放行 |

## 四、数据表

```sql
users(
  id, handle, nick,                                              -- 原文(显示用)
  handle_key UNIQUE, nick_key UNIQUE,                            -- 归一化形式(唯一约束加在这里)
  role TEXT DEFAULT '读者',                                      -- 读者 | 社员 | 编委
  member_state TEXT DEFAULT '',                                  -- 空 | 待确认 | 已确认
  pass_salt, pass_hash,                                          -- PBKDF2-SHA256(盐, 15 万次)
  recover_hash,                                                  -- 一次性恢复码的哈希(可选)
  created_at, last_seen
)
sessions(
  token_hash PRIMARY KEY,                                        -- 只存 sha256(token)
  user_id, created_at, expires_at
)
```

**接入现有表（不重建、不迁移老数据）**

| 表 | 怎么存身份 |
|---|---|
| `tag_votes.voter_key` | 存 `u:<user_id>`（沿用一列，`d:<device>` / IP 只作为历史遗留存在） |
| `comment_likes.liker_key` | 存 `u:<user_id>` |
| `comments` | 新增 `user_id` 列（同时保留 `name` 作历史兼容） |

## 五、接口

| 接口 | 说明 | 要点 |
|---|---|---|
| `POST /api/auth/register` | 注册（handle + nick + 口令 + 是否社员） | 唯一性/保留名单校验、口令 ≥8 位、同 IP 限流、蜜罐 |
| `POST /api/auth/login` | 登录 | 连续失败 5 次冷却 15 分钟 |
| `POST /api/auth/logout` | 退出 | 删会话 + 清 cookie |
| `GET  /api/auth/me` | 当前登录者 | 供前端渲染登录态 |
| （编委）`GET /api/auth/pending` | 待确认社员列表 | 需编委身份 |
| （编委）`POST /api/auth/confirm` | 确认社员 / 改角色 / 开号 | 取代共享钥匙 |

- 会话 cookie：`zz_sess`，**HttpOnly + Secure + SameSite=Lax**，90 天；
- 口令：`crypto.subtle` 的 PBKDF2-SHA256（Workers 原生，不引任何依赖），**不存明文**；
- 找回口令：注册时给一串一次性「恢复码」，让用户自己保存（**不收邮箱**，隐私最小化）。

## 六、前端改动

1. 众注区顶部显示登录态：未登录 →「**登录后可打标与评论**」+ 登录/注册按钮；已登录 →「笔名 · 退出」；
2. 注册弹窗：昵称 + 口令 + 「我是社员」勾选（提示文案随勾选切换，见第三节）；
3. **评论表单去掉「笔名/昵称」输入框**，署名自动取账号笔名且不可手改；
4. **自己的评论不显示「同感」**（前端隐藏 + 服务端拒绝）；
5. 标签 3 个上限按**账号**计（跨设备也只算 3 个）。

## 七、投票人可见性（策略开关，先按保守设）

`src/_data/site.json` 里加一项，默认编委可见：

```json
"zhuzhu": { "showVoters": "admin" }     // admin(默认) | aggregate | public
```

| 取值 | 读者 hover 看到 | 说明 |
|---|---|---|
| `admin`（默认） | 只有计数 | 编委模式下额外显示「赞同者：jwl、蓦流…」 |
| `aggregate` | 「3 人赞同 · 含 2 位社员」 | 有点透明感，不点名 |
| `public` | 「赞同者：jwl、蓦流…」 | 完全公开 |

> 我建议**先 `admin`**：标签多带评价性（打油诗/抽象/忧郁），一旦点名，投票会从"我觉得"变成"我表态"，票量会掉；而编委确实需要名单来防刷、核对。想公开随时改这一行即可，不用动结构。

## 八、清库与上线顺序（顺序不能颠倒）

1. **备份**（已完成）：`sql/backup/2026-09-11-众注数据快照.json`（31 张票的分布 + 2 楼评论全文）；
2. **部署代码**：push → Cloudflare 部署（此后互动需登录）；
   - 建表**不用手工**：`auth.js` 在第一次用到账号时自动建好 `users`/`sessions`/`comments.user_id`（幂等，与 `sql/accounts/01…04` 一致；排错时仍可手工粘）；
3. **开第一个编委号**：`python scripts/zhuzhu-admin.py open jwl --role 编委 --key <旧钥匙>`（昵称自动取名册笔名）；
4. **洗牌**：`python scripts/zhuzhu-admin.py wipe --key <旧钥匙>`（等价于 `sql/curation/05…08`：清票 → 清同感 → 清评论 → 清候选词；**94 词词表与编委已采纳词保留**）；
   - 该动作需要**确认字样**（脚本已内置）且必须编委权限，防止误触；
5. **验收**：见下节；想手动核对数据可跑 `sql/curation/09-核对-已清空.sql`。

## 九、验收清单

- [ ] 未登录时：能看作品、能看标签与评论；打标签/发评论处显示"登录后可互动"；
- [ ] 注册：勾「我是社员」提示变「请用名字缩写或笔名」；输入 `jwl` 或 `蓦流` 被拒并给出保留提示；
- [ ] 登录后：打标签 → 立即变红；刷新 3 次仍红；再点取消 → 变灰且计数 -1；
- [ ] 同一账号换浏览器/手机登录：之前投的票**仍然红**、仍可取消；第 4 个标签被拒（上限 3）；
- [ ] 评论：无昵称输入框，署名 = 账号笔名；自己的评论没有「同感」按钮；换个账号可以同感；
- [ ] 编委：用账号登录即出现管理入口（待确认社员、删评论、整理标签），共享钥匙不再需要；
- [ ] 库里：`tag_votes.voter_key` 全部形如 `u:<id>`；`tags` 恰好 94 条预设词。
