## 1. 提交并推送代码（**这一步只有你能做**）

> 为什么必须是你：推送要 GitHub 凭据，凭据在账号持有人手里；社里也定了「Agent 不代持凭据、不代点 Push」。

在 **GitHub Desktop** 里：

1. 打开 GitHub Desktop → 左上 **Current repository** 选 **wuxu-society**；
2. 中间 **Changes** 页应显示 **32 changed files**（服务端 3 + 前端 3 + 测试 5 + SQL/工具 + 文档 5）；
   *若数字对不上，先别提交，截图发我*；
3. 左下 **Summary** 粘这一行：
   ```
   账号系统 P1：轻身份登录；打标/评论需登录；署名取账号笔名；禁自赞；编委账号取代共享钥匙
   ```
4. 点 **Commit to main**（只存在你电脑里，线上还没变）；
5. 点右上 **Push origin**（**这一步之后 Cloudflare 才开始部署**）；
6. 等 1~3 分钟：Cloudflare → Workers & Pages → wuxu-society → **Deployments**，最新一条变 **success**。

**自查部署成功**（仓库目录跑，`--key` 随便填）：

```
python scripts/zhuzhu-admin.py pending --key x
```

| 返回 | 含义 |
|---|---|
| `调用失败（HTTP 405/404）` | 还没部署好，等一两分钟再试 |
| `{"ok": false, "error": "无权操作。"}` | ✅ **部署成功**（接口在，只是钥匙不对）；顺便说明函数自建表也成功了 |

> ⚠️ **服务端与前端必须一起推**：服务端已要求登录，前端同时提供登录入口。只推一半 → 众注会提示"请先登录"却没有入口。

## 2. 建表（**通常不用手工**）

`functions/api/auth.js` 会在**第一次用到账号时自动建好** `users` / `sessions` / `comments.user_id`（幂等，与 `sql/accounts/01…04` 完全一致）。
所以这一步正常**跳过**；只有在排错或想手工确认时才需要跑 SQL：

| 顺序 | 粘这个文件（可选·排错用） | 预期 |
|---|---|---|
| 1 | `sql/accounts/01-建表-users.sql` | 无报错；`SELECT COUNT(*) FROM users;` → 0 |
| 2 | `sql/accounts/02-建表-sessions.sql` | 无报错 |
| 3 | `sql/accounts/03-评论表加账号列.sql` | 无报错（若报 `duplicate column name` 说明已加过，忽略） |
| 4 | `sql/accounts/04-索引.sql` | 无报错 |

> 怎么知道自动建表成功了？跑第 3 步的开号命令，**能返回 `tempPass` 就说明表已就绪**。

**可选加固（建议现在就设）**：Pages → Settings → Environment variables 里加一个 `ZHUI_PEPPER`（随便一串长随机字符）。
它参与口令哈希但不入库，万一数据库泄露也算不动口令。⚠️ **请在开放注册之前设好**；已经有人注册后再设/改/删，会让那些口令对不上（只能重置）。

## 3. 开第一个编委号（只需一次，用旧钥匙）

在仓库目录（PowerShell）跑：

```
python scripts/zhuzhu-admin.py open jwl --role 编委 --key 你的旧钥匙
```

- 昵称**自动取名册里的笔名**（`jwl` → `蓦流`），不必在命令行敲中文；
- 输出里有 **`tempPass`**（一次性口令）与 **`recoverCode`**（恢复码）：用口令在作品页右上「登录 / 注册」登录一次，**恢复码自己存好**；
- 想给别的社员开号：`python scripts/zhuzhu-admin.py open <缩写> --key 你的旧钥匙`；游客自助注册即可，不需要你开。

## 4. 洗牌（一条命令，或照 SQL 手动）

**推荐：一条命令**（编委账号登录状态或旧钥匙都行）：

```
python scripts/zhuzhu-admin.py wipe --key 你的旧钥匙
```

预期输出形如：`"removed": {"votes": 28, "likes": 2, "comments": 2, "candidates": 4}, "tagsLeft": 94`
—— 票/同感/评论/候选词清空，**94 个预设词与编委已采纳词全部保留**。

## 5. 验收（在页面上走一遍，约 3 分钟）

- [ ] 未登录：页面**右上角（导航栏）**能看到「登录 / 注册」；作品页众注区能看到标签与评论；标签框提示「登录后可打标签」、评论框提示「登录后可发表评论」
- [ ] 手机上点右上角 ☰ 展开菜单，账号入口在菜单最后一项
- [ ] 注册：勾「我是社员」→ 提示变「**请用名字缩写或笔名**」；试 `jwl` 或 `蓦流` → 被拒并提示「属社员，请联系编委开号」
- [ ] 登录后点标签 → **变红**；**连续刷新 3 次仍然红**；再点一下 → 变灰且计数 −1
- [ ] 同一账号**换浏览器/手机**登录：之前投的票**仍然红**、仍可取消；投第 4 个标签被拒（每篇 3 个）
- [ ] 评论：**没有昵称输入框**，署名 = 账号笔名；自己楼下的「同感」不可点；换账号可同感
- [ ] 编委账号登录：每词旁出现「⋯」、每楼出现「删」；悬停标签可看到「赞同者：…」（普通读者看不到）
- [ ] 待确认社员：`python scripts/zhuzhu-admin.py pending --key 旧钥匙` → 看到勾了"我是社员"的申请 → `python scripts/zhuzhu-admin.py confirm <user_id> --key 旧钥匙`

## 6. 出问题怎么办

| 现象 | 处理 |
|---|---|
| 众注提示「请先登录」但没有登录入口 | 前端没推上去 → 服务端与前端**一起**重新 push |
| 注册报「账号操作失败」 | 早期版本用过 15 万次 PBKDF2，超出云端迭代上限会直接失败；现已改为**自适应档位**（90000/25000/5000，把实际次数写进哈希串），push 后即好 |
| 极少数情况自动建表失败 | 手工跑 `sql/accounts/01~04` 后重试 |
| `zhuzhu-admin.py` 报 405 / 空错误 | 账号代码尚未部署 → 等 Cloudflare 构建完成再试 |
| 想临时关掉众注 | `src/_data/site.json` 里 `zhuzhu.enabled` 改 false 并推送 |
| 想找回洗牌前的数据 | 见 `sql/backup/2026-09-11-众注数据快照.json`（逻辑快照：票数与评论全文） |
| 想改"谁赞同了哪个标签"的可见性 | 改 `site.json` 的 `zhuzhu.showVoters`（`admin`/`aggregate`/`public`）→ `npm run sync-zhuzhu` → 推送 |
